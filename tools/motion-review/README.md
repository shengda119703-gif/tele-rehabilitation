# 动作视频上滑回看 · 1.0.0

独立的本地回看工具，不替换正式 Qt、APK 或公网 UI。用于查看已导出的关键点、人体/杠铃计算结果；不发起推理、付费模型调用、患者记录写入或云上传。原始文件不覆盖，输出目录必须是新目录。

## 使用

使用已有 NumPy 的 Python 环境：

```powershell
python tools/motion-review/build.py --analysis '<包含分析批次.json的目录>' --output '<新的本地输出目录>'
python tools/motion-review/serve.py --root '<本地输出目录>' --port 14929
python tools/motion-review/test_metrics.py
node tools/motion-review/test_review.cjs http://127.0.0.1:14929/ '<本地检查输出目录>'
```

浏览器检查复用项目 Playwright 和本机 Edge。服务器只监听 127.0.0.1，支持 MP4 Range/206 和拖动进度；不自动暴露到公网或局域网。生成数据、视频、CSV、截图、provenance.json 不加入 Git。

## 交互与呈现

- 上方视频；底部面板可拖动、上滑、鼠标滚动或按 Enter 展开。展开后可滚动查看数据，播放控制固定在底部。
- 当前数据和全段统计明确分开；节奏和平均功率始终标记全段。暂停、拖动进度、切换视频都会按同一时间索引更新数据和骨架。
- 关键数据配评价；点指标看曲线，点重点评价跳到对应时刻。正/侧面是独立视频，不做同步双机融合。
- 角度与标注使用最近的已观测采样，最多保持0.30秒；图表缺测断开，不生成中间观测。
- 保留生成样片来源；不展示完成次数，不把角度对称性写成真实左右腿力分配。
- 提供 CSV 和可访问的数据表，结论除颜色外还有文字；可用键盘操作，遵循减少动画设置。

视觉按用户参考：深灰紫面板 `#292630`，数据底 `#36323e`，正文 `#f7f7f9`，次级文字 `#c3becb`，绿色评价 `#40e5b5`，琥珀评价 `#ffd091`；绿色块 `#099b6d`（白色大数字对比3.55:1）。微软雅黑正文与大号等宽数字对齐；不是通用首页重设计。纯视频区不放数字 HUD，下方用大数字、短评价、双列网格。桌面保留同一竖屏播放器，左侧选视频。标准控制图标来自 Bootstrap Icons 1.13.1，路径原样复用，MIT许可随UI保留；不复制Keep品牌或手机系统栏。

## 输入与计算

输入为原软件导出的 `软件原始结果.json`、`逐帧关键点与动作阶段.json`，以及 `v3_75kg180cm` 下已保存的几何、人体模型、杠铃片轨迹。身体参数从已保存模型读取，不从人物外观猜测；原功率和速度逐值复用。

- 二维角度：先将规范化坐标恢复到1280×720，再计算夹角；显示使用因果0.32秒中位数。角度缺失时不沿用旧值。
- 膝部对齐：向内相对同侧髋踝连线、向外相对同侧足部外缘，按已保存身高标尺换算。屈膝≥25°、连续至少3个超阈值采样才给偏移提醒；全段统计只在屈膝可评价区间选取。
- 骨盆位移：1.2秒连续观测窗口范围。正面是左右，侧面是前后；侧面不按左右晃动评价。步行肩髋左右高低只用正面，耳肩前移只用侧面。
- 轨迹：杠铃片中心相对片头的水平位移，沿用原直径标尺；方向是画面左右，不猜解剖前后。
- 节奏：观测速度阈值±0.03m/s；连续移动至少0.24秒、位移至少2.5cm。首尾截断和缺测间隔不作为完整时段。用完整时段中位数生成提升/下放用时，只有相邻下放→提升对才生成用时比。
- 左右起身时差：完整提升段内，两侧膝角各自超过本侧伸展幅度20%的首个观测时间之差；每侧有效伸展至少8°。不是左右发力时差。
- 速度变化：至少两个完整提升段、前后位移比0.7–1.3，才比较平均提升速度；不是疲劳或疾病诊断。
- 起身配合：近0.32秒骨盆上升速度>0.05m/s、负重/人体速度>0.03m/s、近0.48秒骨盆上升>2cm时，评价同窗口躯干前倾变化；不从俯身阶段误报“髋先起”。
- 局部角度波动：最近0.56秒二次曲线拟合残差，至少4个连续观测。输出轨迹平顺性沿用原高度拟合残差。

上述评价阈值用于界面描述，不是临床金标准。所有方法、来源SHA256、时段、缺测和值的来源保存在私有输出 `provenance.json`。缺乏完整时段的统计保留 null，不替换为0。

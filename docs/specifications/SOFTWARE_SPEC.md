## 0. 冻结后的产品目标

核心特色不变：自动康复评估、自动执行已设置的训练指导、少量可解释的动作质量监督及历史报告。轻量活动管理仅做可见久坐提醒、站立与家中可见步行任务。基础安全只做已观察到的床边活动、可解释风险提示、疑似低位/跌倒报警与人工确认。

首版条件：单人在受控画面中主动使用；一台电脑；不新增必需硬件；所有场景可以绑定同一内置摄像头，但只能依次演示，不表示同时监控四个房间。

**显示承诺：没有启用的场景必须显示“未启用/未监测”，绝不能显示“正常/安全”。当前输入看不见的房间，没有被系统覆盖。安全事件若已产生，切换模式、隐私暂停或断流都不自动关闭它。**

### 首周必须做
- 场景选择、摄像头枚举/刷新/选择、预览、拍摄配置、手动机位确认、开始/停止。
- 摄像头未购买时也能运行；选内置摄像头。之后切外接UVC设备不重写业务算法，但重新配置并验证测量表现。[N1,N2]
- 本地录像回放，与实时来源永久区分；不得把回放、合成事件伪装为实机效果。
- 坐站和单侧肩外展两项动作；自动记录、训练提示、报告保存和重开。
- 可见久坐→站立/步行任务；床边演示；安全事件演示与确认。
- 断线/未知/未启用/隐私暂停的明确状态，历史记录可靠保存。

### 首周明确不做
多摄像头同时运行、RTSP现场部署、雷达集成/采购、全屋连续覆盖、跨摄像头身份重识别、疾病诊断、跌倒概率预测、自动开处方、模型训练、精确三维重建、真实肌力或负重、手机App、云平台和远程报警。

雷达和多流只放在`../plans/FUTURE_EXTENSIONS.md`，不在主依赖、不在启动检查、不在本周验收。任何后续真实卫生间部署都需要另做隐私与环境验证，不能把着衣模拟场景说成实际洗浴监护。

## 2. 冻结技术选型

| 层 | 方案 | 范围 |
|---|---|---|
| 环境 | Windows、独立Python环境，候选Python 3.11 | 保留可运行工程，避免破坏科研环境 |
| 输入 | OpenCV + `cv2-enumerate-cameras` | 内置/外接本地摄像头与本地视频 |
| 姿态 | 沿用`YOLO11n-pose`，本地官方权重 | 一套预训练模型，COCO17点；不是跌倒/康复诊断模型 [S1,S2] |
| 跟踪 | ByteTrack，仅当前运行上下文 | track_id不是身份；切场景/源/机位/回放跳转时重置 [S4] |
| 计算 | NumPy及可测试状态机 | 首周不训练时序分类器 |
| 界面 | PySide6 Widgets | 主线程只管UI，工作线程处理采集和推理 [S7] |
| 保存 | SQLite + JSON/CSV/HTML | 默认不录全天视频 |
| 提示 | 本地WAV/MP4 | 不调用LLM生成实时医疗建议 |
| 测试 | unittest/pytest、人工视频标注 | 单元测试不等同实机或临床验证 |

换内置/USB摄像头不要求更换模型。视角、裁剪、照明或图像质量变化可能使原规则失效，必须重做机位与结果检查，不能保证“换摄像头精度不变”。[N1,N3]

已有MediaPipe模块能工作时可通过统一PoseFrame适配继续使用，不同时再造两套完整产品。RTMLib/RTMPose仅是首日明确必要时的备选。Sports2D用于离线参考、Kinovea用于人工视频检查，均不设为必装。许可需分别检查Ultralytics、Qt及权重；开源不是无条件闭源商用。[S8,S9,S15-S18]

### 2.1 模型资源分级：本周不增加主依赖

| 层次 | 本周直接使用 | 现成资源怎么用 | 不应误解为 |
|---|---|---|---|
| 姿态估计 | 已冻结的`yolo11n-pose.pt` | 人体框＋COCO17点；同一输入只运行一次模型 [R1,R2] | 膝/肩的诊断模型，或现成跌倒模型 |
| 几何测量 | NumPy纯函数 | Sports2D只作独立离线参考；Kinovea作人工视频标注工具 [R3,R4] | 两套算法一致就证明临床准确 |
| 动作过程 | 自写状态机 | AIGym参考接口/阈值思路，不直接照搬计数终点 [R5] | 还需要一个通用动作识别模型才能计数 |
| 动作质量 | 少量专业规则＋个人目标 | STGCN-rehab仅在稳定版之后研究；需要其骨架和预处理 [R6] | 下载权重即可评价本项目两项动作 |
| 活动与报警 | 有效时间积分＋区域/时序规则＋人工确认 | 老跌倒项目只研究设计；不直接粘贴老环境或接入其权重 [R8] | 静态躺姿等于跌倒，更不等于提前预测 |

**沿用YOLO11是减少集成风险，不是断言它最新或对所有动作最准确。** 官方有其他模型版本，本周不以“更新”为理由迁移。[R1]

Sports2D、Kinovea可以不装，手工视频标注也能开始验收。STGCN-rehab、REHAB24-6、RTMPose等不进入`requirements.in`、首次启动、模型自动下载或第1天验收。各资源的地址、输入差异与授权注意事项见`../plans/RESOURCES_AND_UPGRADES.md`；没有阅读或下载它们也必须能启动主程序。

### 2.2 许可与来源先检查，不因为“Demo”跳过

代码、权重、训练数据、演示视频分别记录来源、版本和许可。Ultralytics采用AGPL-3.0/Enterprise路线；按实际使用方式核查，不把“研究演示”当成所有资源的自动授权。[R1] 外部数据不能不经授权放进安装包；未知来源`.pt/.pth`不加载。资源名出现在任务书中不代表已获得使用权或已下载实测。

第一次只完成：选场景→选内置相机→预览→机位检查→一次任务→保存→关闭程序→重开报告。不得先搭空白多房间九宫格。

按钮行为必须明确：
- 刷新设备仅枚举，不轮流打开所有摄像头探测，不改变当前视频。
- 预览显示画面，允许同一模型做站位检查；正式业务计时/计数/风险引擎不运行，界面写“预览，尚未开始分析”。
- 检查站位含手动确认。不能由模型粗略识别人像就宣称精确侧身90°。
- 开始必须有有效来源、匹配机位、必要区域、清楚的参与者。缺项具体说明。
- 停止保存已完成内容；部分重复记中断/无效，不能补成完整。停后默认释放相机，返回未打开。
- 隐私暂停停止获取新画面并释放设备，不只是遮住UI；恢复重新预览，不自动续接计时。

## 5. 摄像头枚举、身份匹配与刷新

### 5.1 后端和索引必须成对使用
使用`enumerate_cameras(explicit_backend)`获取名称、path、vid、pid、index、backend。Windows先在DSHOW或MSMF中选一套实测可用后端；失败时人工选择另一套并重新枚举，不能沿用旧索引盲目自动回退。[N2,N3]

```python
import cv2
from cv2_enumerate_cameras import enumerate_cameras
items = list(enumerate_cameras(cv2.CAP_DSHOW))
# selected来自本次items中的真实条目，而非下拉框行号
cap = cv2.VideoCapture(selected.index, selected.backend)
```

官方仓库说明CAP_ANY可能产生含后端编码的索引，默认枚举还可能把同一物理设备列在多个后端中。因此不手工加减700/1400，不混用DSHOW/MSMF索引，不把“列表第2行”直接当摄像头2。[N2]

### 5.2 持久化不是永久固定编号
保存设备path和backend为主要匹配线索，name/VID/PID用于展示或辅助提示。index仅本次解析结果，不能在新启动/热插拔之后无条件使用。VID/PID和同名都不唯一，两个相同摄像头不能自动选第一个。

解析规则：
1. 同后端、同非空path且唯一：可作为本次候选。
2. path缺失、改变、找不到或多个匹配：要求人工选择，禁止静默切到索引0或其他相机。
3. path是设备定位线索，不是跨电脑/USB端口永不变的硬件序列号。即使找到也仍需预览确认。
4. 后端变化视为重新绑定。打开前重新枚举定位当前index；设备拓扑此时发生变化，返回需重选而非连续猜索引。
5. 枚举成功不等于设备能打开，更不等于视野符合测试要求。

### 5.3 状态和常见错误
区分未选择、未找到、打开失败、权限可能受限、被其他应用占用、取流超时。底层不能确知原因时写“打开失败，请检查权限或占用”，不伪造精确错误原因。[N4]

支持内置/外接/虚拟相机时显示实际设备名；IR/深度专用输入不当RGB直接使用，用户应选择有正常彩色画面的一路。不要通过遍历0..9并逐个开启的粗暴方式作为默认刷新。

## 6. 切换是一笔事务，不是换一个下拉框文字

场景、设备、录像、后端、机位、旋转、裁剪、动作、测试侧发生变化时执行同一个切换入口。首周即使只是同摄像头换场景，也先完整停止和重新打开，牺牲一点切换速度换取清楚的生命周期。

```text
冻结开始按钮；取消尚未执行的旧反馈
→ 停止接收旧分析结果；使旧generation失效
→ 等待工作线程在受控边界停止；结束旧任务并持久化
→ 中途动作标中断，历史已完成记录与待处理警报保留
→ 清空最新帧、平滑、跟踪、计数、连续久坐/任务计时
→ 确认旧VideoCapture真正释放
→ 使用重新枚举的设备打开新输入
→ 只进入PREVIEW
→ 加载或新建对应机位，人工确认
→ 用户点击开始，建立新的run/session
```

**旧worker没有确认停止或release失败时，不允许打开第二个输入。** 不用`QThread.terminate()`强杀持锁线程；若目标后端read可能永久阻塞，将实际采集隔离为可终止并确认退出的子进程。采用子进程只为恢复阻塞，不代表多路并行。[N3,S7]

每个包带`generation/run_id/scene_id/source_ref/stream_epoch/seq`。消费端只接收当前上下文，且seq严格增加。旧推理、旧Qt信号、旧音频即使迟到也不能污染新会话。无需每次重新下载/训练模型；模型权重可留内存，tracker和业务状态必须重置。[S4,N5]

预览帧与正式会话边界也隔离；点“开始”前清空最新帧槽、增加generation并通知生产者/推理端，仅接收新边界之后采集的帧，不给旧缓存改标签充作新帧。点“开始”前的低位或半次动作不能成为正式计数的前半段。停止后返回预览再开始，也重建业务时间线。

若保存失败，先停止采集与分析，保留可恢复的待保存快照并显示错误；不能声称“保存成功”，也不销毁未保存数据后继续切模式。用户明确丢弃才可继续，并记录操作。

设备重连恢复后仍是PREVIEW，需要重新确认和开始，不能接着旧半次动作或给缺测期间补活动时间。换设备不会删除个人档案/目标，但新机位不自动取得旧测量基线有效性。

## 7. 场景＋设备＋机位配置

把设备表和机位表分开：一个设备有多个场景机位；每个场景可设默认机位；第一次没有设备时默认值为null，不能默认绑定0。

机位配置至少保存：
- scene_id、profile_id、device_ref（path/backend，或明确文件引用）。
- view（正面/侧面/固定观察）、exercise_id、测试侧、placement_revision。
- requested_width/height/fps与实际frame_shape、驱动reported_fps、实测received_fps分开。
- 原图方向、旋转/裁剪/视角设置、镜像预览；模型和规则版本。
- 原图归一化ROI、可选经授权参考图；区域确认时间、操作人、当前run确认状态。
- 人工目标与活动许可；不设置的医疗目标保持null。

**机位被移动可能无法自动可靠发现，因此每次打开、切换或恢复至少人工确认一次。** 自动画面变化检查只能辅助，不保证发现屏幕角度变化。

### 坐标约定
ROI保存为“原始、未镜像画面”的归一化坐标。UI等比例缩放时先扣除letterbox留白，再逆镜像映射，最后归一化；点到黑边不生成ROI。

纯分辨率改变、宽高比相同且确定视野/裁剪不变时，可以将旧ROI作为待确认候选映射。宽高比、镜头、取景裁剪、电子防抖/数字变焦变化时不直接复用。即使同宽高比也不保证相机输出视野完全相同，必须预览确认。

角度计算始终用同尺度原图像素坐标，不直接用x按宽、y按高的归一化坐标算角度。镜像仅影响显示，解剖左右侧标签不交换。

## 8. 真实参数、视频时间和数据质量

### 实际分辨率和FPS
请求1280×720、30FPS作为内置相机起点，不把这些值写死在算法里。以实际帧shape为尺寸；`CAP_PROP_FPS`记录为驱动报告值，另按接收时刻测量有效FPS。属性能否生效取决于设备/驱动/后端。[N3]

自动对焦、曝光、夜视、广角畸变等变化可能影响测量。这里只承诺输入协议兼容，不承诺USB一定更准。内置相机只拍到上半身时，先测肩外展；坐站、步行、地面事件应标无法验证，不伪造下肢数据。

### 最新帧与时间
- 一个采集槽，容量1；实时只分析新帧，旧帧被覆盖。
- LIVE使用单调接收时间积分，另存UTC显示；不把接收时间当真实曝光时间。
- REPLAY使用解码媒体时间（PTS优先）。OpenCV时间戳不可用/非单调时，应明确标时间不可用；仅在验证恒定帧率的文件允许注明`frame_index/fps`近似。不得用推理耗时给回放计活动时间。
- 拖动进度、循环、换文件、恢复播放导致不连续时新建epoch/会话；不同播放速度不能改变同一动作的媒体时长。
- source_kind = LIVE_CAMERA / REPLAY_FILE / SYNTHETIC，另存usage_context = SELF_USE / CONTROLLED_DEMO / TEST；真实摄像头拍演示仍是LIVE_CAMERA+CONTROLLED_DEMO，不叫真实家庭长期监护。

设备：UNSELECTED / CONNECTING / PREVIEW / ONLINE / STALE / OFFLINE / PRIVACY_PAUSED / ERROR。
场景：INACTIVE / PREVIEW / ACTIVE / INTERRUPTED / NEEDS_SETUP。
人物/行为：NO_PERSON_DETECTED / MULTI_PERSON / UNKNOWN / 已有效识别状态。
“未检测到人”不是证明房间无人；OFFLINE不是正常；INACTIVE不是正在监测。

## 9. PoseFrame统一格式

YOLO后端使用：`result.boxes.xyxy`、`result.boxes.id`、`result.keypoints.xy`、`result.keypoints.conf`。[S2]
无box、无id、无关键点时返回明确空值，不能抛异常后直接退出整个程序。

```python
@dataclass
class PosePerson:
    track_key: str
    bbox_xyxy_px: list[float]
    keypoints_xy_px: list[list[float]]   # 17x2，原图像素坐标
    keypoints_conf: list[float]          # 17；不是动作正确率
    roi_tags: list[str]

@dataclass
class PoseFrame:
    camera_id: str  # 当前选择的逻辑设备
    scene_id: str
    run_id: str
    generation: int
    epoch: str  # 按第6节隔离；切上下文后旧数据被拒收
    seq: int
    analysis_time_ms: float              # live用monotonic；replay用媒体时间
    frame_size: tuple[int, int]
    source_kind: str
    people: list[PosePerson]
    inference_ms: float
    quality_status: str
```

COCO17关键点：0鼻；1/2左右眼；3/4左右耳；5/6左右肩；7/8左右肘；9/10左右腕；11/12左右髋；13/14左右膝；15/16左右踝。[S2]
内部统一左右是受试者解剖侧。镜像只影响显示；显示层点击的ROI/选人坐标必须逆变换回原图。首周最简单是关闭镜像；不要既翻转原图又交换关节名称。

### 9.1 骨架契约必须显式，点数相同不代表语义相同

统一输出增加`schema_id`（首版固定`coco17-v1`）、`coordinate_space`（`raw_image_pixels`）、`keypoint_order_version`、`model_manifest_id`；模型文件SHA256、关键点顺序及左右定义保存到会话快照。外部适配器未提供正确契约时拒绝进入业务，而不是猜测关节点顺序。[R2]

COCO17能提供本版所需的主要关节，但没有完整足跟/足尖、手指或肩胛结构；缺少的点不能靠复制踝点“补齐”。本周不开发精确足弓、足旋前、真实脚跟抬升等功能。[R2] 若以后用不同骨架，明确按语义映射并保留缺失掩码，不把节点数相同当作兼容证明。

### 9.2 同时保留局部动作与全局位移

运行内存中的短历史保留三类信息，避免为归一化而抹掉安全事件线索：

| 数据 | 用途 | 规则 |
|---|---|---|
| 原图关键点、人体框、根节点中心 | 场景位置、身体下降、ROI关系 | 不被局部归一化覆盖 |
| 以骨盆等为参考的相对姿态 | 动作形状与可见代偿 | 基线尺度在有效准备阶段确定，记录版本 |
| 时间、可见性/有效掩码、原图尺寸 | 速度、间隔、缺测和复现 | 缺失保留，不用零点冒充有效坐标 |

可用肩/髋中心轨迹描述整体运动，但不能称为精确人体重心。下降速度按**同一人、同一机位、相邻有效观察、真实时间差**计算；需要无量纲速度时除以记录好的个人基线尺度。不能每帧把人体重新居中并缩放后，仅用这些相对坐标寻找整体下降。

## 10. 预处理和坐标约定

### 10.1 质量门控
按动作列出必要关节。只对这些关节逐项检查：有限数值、在画面合理范围、置信度、帧间跳跃、遮挡与人选一致性。
初始`kpt_conf_min=0.50`只是待调工程值，不是50%医学可信度。无效关节的角度返回null，不输出0°。
稳定准备至少约1秒；连续必要点丢失则暂停动作评价，超过允许短空档判本次重复无效。不得用最后一帧骨架继续完成计数。
同一侧面任务固定近侧并记录左右侧，不能每帧切换“更清晰”的一条腿。

### 10.2 角度计算
全部二维测角先转原图像素坐标。MediaPipe的x按宽、y按高归一化，不能在非正方形画面直接对归一化坐标算角度。[S9]

```text
v1 = A - B
v2 = C - B
angle = degrees(acos(clip(dot(v1,v2)/(norm(v1)*norm(v2)), -1, 1)))
```
零长向量和无效点返回null。
- 膝内部夹角：∠髋-膝-踝；伸直约180°。
- 膝屈曲投影角：180°-内部夹角。本定义不测超伸负角。
- 肩抬举投影角：∠髋-肩-肘；手臂自然下垂近0°，不是∠肩-肘-腕。
- 肘内部夹角：∠肩-肘-腕；屈肘补偿使用相应转换或内部夹角差。
- 躯干投影倾角：肩中点-髋中点相对校准垂直方向；不称为真实骨盆/脊柱三维角。

### 10.3 时间滤波
首版使用时间常数EMA：`alpha=1-exp(-dt/tau)`，初值tau约0.12秒；按实际时间dt而不是固定帧数。过大空档/相机epoch改变时重置。实时滤波与最终报告算法版本记录清楚。
不为缺失段生成安全事件证据；报告最大幅度优先用有效动作短时间窗口统计，不取明显噪声单点峰值。

### 10.4 视角与尺度
用户手动确认正面/侧面，软件加粗略朝向检查；不要声称从肩宽就能精确知道偏转几度。机位不符则不出精确角度。
ROI归一化只用于保存区域；角度使用像素，运动幅度/速度可用个人基线躯干长度归一化。未标定不输出厘米、米/秒或真实负重。

### 10.5 缺测按指标处理，不把遮挡写成动作问题

整场状态与逐项指标有效性分开。比如肩/髋/肘可靠但腕被遮挡时，抬举角可能仍可计算，肘部纠错则不可判断；不能因为某一非必需点缺失让所有有效结果归零，也不能继续播报无证据的纠错。动作计数是否继续，依该动作的必要点清单和缺测时长决定。

只在误差证据稳定存在、达到时间条件时提示。若视角不符或数据不足，先输出“无法评价及原因”，而非“动作不合格”。首次调试应显示必要点置信度、当前阶段、主要指标、拒测原因和实际推理速率，隐藏在一个“调试详情”面板即可，不新增复杂页面。

实时路径只允许使用当前与过去数据；EMA为因果滤波，不用前后帧双向平滑伪装实时。若最终报告另用离线平滑，记录算法版本，并把离线结果与实时触发记录区分；绝不事后改写已经发生的报警时间。

## 11. 核心：自动评估、训练指导与质量监督

### 11.1 同一引擎的两种使用模式
评估模式：说明任务、开始/停止、质量提醒；不在计时测量中不断教用户改变表现。输出次数、时间、投影幅度、数据有效性与可见问题。
训练模式：加载人工确认的训练计划；示范、计数、节奏、少量实时纠正；训练结束保存报告。
历史比较只比较相同动作、机位、测试侧和规则版本；不兼容时提示“条件不同，不宜直接比较”。

### 11.2 训练计划必须可配置
字段：exercise_id、测试侧、目标次数/组数、幅度目标、节奏范围、是否允许扶物、是否需要陪同、声音启用、停止说明。
用户选动作，不训练动作类别识别器。目标幅度为null时只测量，不自动宣称“未达正常”。初始校准只使用参与者允许且舒适的姿势，不要求患者做到最大活动度。

### 11.3 坐站状态机
```text
SEATED_READY → RISING → STANDING_REACHED → LOWERING → SEATED_READY
                           ↑
                   此时记一次“完成起立”
```
- 准备：固定座椅、指定侧面、固定近侧；记录舒适坐位和站位的膝角/髋高度基线。
- 起立：髋部上移并且膝屈曲减少，持续达到最小有效时间后进入RISING。
- 达到站位：接近个人站位基线并稳定，记一次完成起立。默认是动作任务定义，不是医学“完全伸直”诊断。
- 只有观察到返回坐位后，才允许计下一次。
- 起立中又坐下但未达到目标：记“部分起立”，不删除尝试记录。
- 当前重复若必要关节丢失/人物换人：记无效，不补全。
- 结束在第N次站位时，不因没有再次坐下而把第N次作废；下降阶段指标此时为null。
- 非标准化椅高、扶手、脚位、终点定义下，标题为“居家坐站任务/训练”，不得引用标准5次坐站常模。

输出：完整起立数、部分尝试数、无效尝试数、每次起立时间、已观察到的下降时间、主要投影角、数据有效时间占比。
首版可见质量项：目标站位未达到；下降节奏不符合已设目标。不要用腕部靠近扶手直接推断实际受力，允许人工记录是否使用双手。

### 11.4 正面肩外展状态机
```text
REST → RAISING → PEAK/HOLD → LOWERING → REST
```
- 抬举角与往返分期必要点：测试侧髋、肩、肘；肘屈曲指标另需腕；躯干侧倾另需双肩/双髋。按指标分别判有效，不能因腕点缺失就把可靠的抬举角写成0°。
- 回到REST后记一次完整往返。
- “发生完整往返”与“达到幅度目标”分开。未达到目标的往返仍要记录，不能让计数器一直不动。
- 未设置目标时，只输出本次幅度与历史差异。
- 质量规则最多两条：抬臂时可见肘屈曲增加；躯干投影侧倾超出人工配置范围。
- 名称用“上臂相对躯干的二维投影抬举角”；不称盂肱关节精确活动度；不测肩胛上回旋。

### 11.5 不直接照搬AIGym计数
当前查阅的AIGym源码在角度由up状态进入down阈值时增加次数。[S3] 对坐站的“完成起立”或肩外展的“完整往返”并不天然等价。
参考其输入和绘制方式，但把状态机写入项目自身的可测试纯逻辑。将关键点置信度、迟滞、时间、完整回位、无效片段和个体目标加入，不调用第二次模型重复分析同一帧。

### 11.6 反馈策略
优先级：疑似安全事件 > 数据质量 > 当前最主要动作问题 > 节奏 > 鼓励/完成提示。
一次只播一条。建议起步：相同问题连续出现约0.5秒再标记；语音冷却约8秒；与动作阶段关联。上述为工程参数，不是临床界限。
使用本地WAV或经验证的本地语音引擎。动作示范视频自行拍摄并复核或使用已获授权素材；未提供时标“待配置”，不能偷偷从网络搬运。
不说“你的臀中肌无力/肩袖损伤/即将跌倒”。说“本次上举时躯干侧倾增加”“当前画面无法可靠测量”。


### 11.7 质量结果是多个独立字段，不是一个总分

首版每次重复至少保存以下互相独立的结果；这是本应用需要实现的契约，不是第三方SDK自带字段：

| 字段 | 示例 | 含义 |
|---|---|---|
| `observation_status` | `VALID / PARTIAL_OBSERVABLE / UNUSABLE` | 这一段是否有足够观察证据 |
| `observation_reasons` | `occlusion / out_of_frame / wrong_view / identity_ambiguous / stream_gap` | 为什么不能可靠判断 |
| `completion_status` | `COMPLETE / PARTIAL / INTERRUPTED / UNASSESSABLE` | 往返/起立任务是否完成；无法判断不强填“部分完成” |
| `target_status` | `MET / NOT_MET / NOT_SET / UNASSESSABLE` | 是否达到**人工已设置**的目标；目标不存在不算失败 |
| `metric_validity` | 每个指标的`valid/reason` | 某指标无效，不必否定其他独立有效指标 |
| `issues` | 多个规则证据，或空列表 | 同一动作可以同时屈肘与侧倾；不是疾病标签 |

`issues`每项保存`rule_id、phase、start/end_time、metric、measured_value、configured_limit、evidence_valid、feedback_emitted_at`。无目标或证据不足时，不触发相应“未达标/错误动作”规则。`evidence_valid`不是模型给出的临床置信概率。

**例：**完整往返中髋/肩/肘可靠、腕被遮挡，可以记录完整次数和抬举角，但肘屈曲指标及其纠错为无法评价；若完成过程的必要点也缺失且超出允许空档，则为`UNASSESSABLE`，不能补全。目标没设置时为`NOT_SET`，不是“活动度不足”。

### 11.8 规则可配置，但不能边做边改标准

把每项动作的必要关节、状态、进入/退出迟滞、最小持续时间、个人目标、反馈冷却和提示文案放入动作配置。每次开始时保存不可变配置快照；运行中改动作目标、规则、机位或侧别，走第6节结束/重新开始流程。现有`configs/exercises.example.yaml`中的`keypoints`是动作涉及点的清单，实际应用应按本节细分计数与各指标必要点，不以整张清单一刀切地让所有指标失效；新增契约由Codex实现。

允许问题多标签并存，但一次只播一个最高优先级反馈；其余保留在报告。先写可见事实：“本次上举过程中出现屈肘”；不要让固定的健康人阈值覆盖术后限制，更不要把屈肘解释成肌力不足。首版不提供“姿势标准总分”或自动进阶处方。

## 12. 活动场景：久坐→站立/步行

本节只在activity已开始时运行，不在康复/卧室/安全模式后台累计。

判断可见坐位需座椅区域及姿态证据；站位需足够的躯干/下肢；步行需直立、持续平移与腿交替证据。只看到上半身移动时标“可见移动”，不核销严格步行任务。

用户在单人区域选定目标。ByteTrack只做当前run内连续性辅助，不跨模式、重连或不同设备识别人。多人、出画、失跟使个人归属不明时暂停并重新确认。

时长只累计相邻两次有效、同身份/同状态且间隔不过大的观察；缺测、切模式、隐私暂停、离线不计。历史可见时长保留，但连续久坐计时在中断后不直接恢复。活动任务原状态记INTERRUPTED，可重新开始新任务；自报完成与视觉核实分开。

行为目标示例：可见坐位45分钟→提醒→用户选站立60秒或步行120秒。它们是可调整的演示/行为参数，不是通用处方；提供活动许可、延期、拒绝、停止。

为演示可以建缩短时间的独立`demo_profile`，必须一直显示“演示阈值”并写入报告；不可偷偷加速时钟或伪造已坐45分钟。

## 13. 卧室与安全演示

### 卧室
先手工圈床/床边/出口/地面关注区域，再运行：VISIBLE_IN_BED → BED_EDGE_SIT → BED_EDGE_STAND → OBSERVED_EXIT。遮挡/被子导致UNKNOWN。“没看见人”不当已离床，“尚未观察返回”不解释为一直在厕所。

没真实床时可以展示区域状态逻辑，但结果标“模拟区域演示”。不把普通坐椅起身的视频写为实测床上翻身或睡眠监测。

风险提示采用可解释规则：经人工配置需协助者的夜间已识别起身等。不输出未来跌倒概率，不把关键点置信度当风险概率。

### 安全演示
只在safety_demo运行当前场景的疑似异常低位/倒地规则；其他模式没有隐形后台安全覆盖。可在康复模式内保留立即手动停止和“数据异常暂停”，但不要将其包装成全天跌倒监护。

输入：人体中心下降、躯干方向变化、地面关注区、持续低位、床椅排除区、数据有效性。两条入口：观察到下降后的异常低位；没有看到下降但持续异常低位。都只输出疑似和人工确认，不将髋点落在地面ROI等同于真实接地。

事件产生：OPEN→ACKNOWLEDGED→RESOLVED，ACK仅已查看。存来源、场景、机位、证据和测试标签。不因为切模式/断线/人消失自动关闭，不因为尚未处理就阻塞所有其他页面。新模式中待处理事件仍可查看；重复旧帧不能制造新事件。

安全提示只承诺本地界面/声音。未接通远程通道不显示“已通知家属”，更不冒充急救服务。测试采用安全的受控低位动作或明确标记的回放，不诱导真实跌倒，不在湿地测试。

### 安全时序的实现边界

短历史窗口用秒定义，而不是把“30帧”当成固定时长；推理速率变化时，30帧代表的时间会变化。可从约1—3秒历史作为调试起点，但这是待验证的工程参数，不是安全标准，不能要求先等满窗口再进行任何提示。

输入保留第9.2节的原图位移和姿态形状。长空档、失跟、机位移动后不拼接轨迹、不插值补出下降；状态降为未知，已存在的事件仍保留。姿态关键点高置信也不能排除遮挡错误或正常坐/卧行为。

记录`evidence_start_time、first_observed_abnormal_time、event_emitted_time、human_ack_time`；真人回放/人工标注另记时间来源。没有观察到下降过程就写“持续异常低位，过程未观察”，不编造摔倒起点。规则利用的是历史和当前证据，不能把事后倒地识别宣传成事前预测。

## 14. 存储、报告和隐私

SQLite：devices、scene_profiles、sessions、repetitions、activity_intervals、tasks、events、config_snapshots。单一写入队列，关键停止/切换记录要有写入结果，不能fire-and-forget后宣布成功。

sessions必须带scene_id、submode、device_ref、backend、resolved_index_at_start、source_kind、usage_context、generation/run_id、profile_version、实际画面尺寸、ROI确认记录、模型/规则版本、开始/结束与中断原因。

报告按同动作/侧别/机位/可比版本比较。换设备先建新基线，不把不同条件下几度变化称康复改善。所有报告明确可见时段和数据缺失，不输出真实肌力/负重或诊断。

默认不保存连续视频；参考截图、关键点回放和事件片段由用户选择并告知用途。设备路径可含设备实例标识，不默认写入公开日志。SQLite不是默认加密；保护本机目录权限。隐私暂停释放相机并清空未授权视频缓冲；历史已同意保存的报告不自动删除，另提供删除入口。

### 14.1 本周增加轻量调试导出，不建设大型训练平台

优先复用现有会话保存，在用户明确选择“保存本次调试数据”时，提供一个导出按钮。原始视频、逐帧骨架、截图分别选择并记录同意；日常模式默认不连续保存它们。无需新建标注网站或下载公开数据才能使用。

```text
session_export/
  session.json        # 来源/场景/设备引用/机位/版本/配置/同意范围
  metrics.jsonl       # 有效观察的时间、指标、有效掩码、动作阶段
  repetitions.json   # 完整/部分/无法评价及个人目标、问题证据
  events.jsonl        # 建立、更新、已查看、关闭；保留真实触发时间
  poses.jsonl         # 仅明确授权时导出原图关键点/框及置信度
  source.mp4          # 仅另行授权且实际录制时存在；不是默认文件
  annotations.csv    # 人工评阅结果；可先用普通表格，不要求新UI
```

模型预测写在`predictions/metrics`，人工标注单列`annotation_origin=human`、标注者、版本和原始证据时间，禁止用模型自己的标签当标准答案。没有骨架/原视频保存许可时，照常输出已同意的指标报告；明确不能用指标重新训练视觉前端。

每段数据至少有：匿名参与者ID、recording/session ID、来源类别、使用情境、动作/侧别、设备与机位版本、原图尺寸、时间基准、`schema_id`、模型文件hash、规则和预处理版本。公开日志中设备引用应脱敏，不输出设备完整路径或参与者姓名。非有限浮点序列化为`null`并带无效原因，不输出非标准JSON的NaN。

SQLite优先在原表增加可空字段或JSON证据，不重写数据库框架。先备份再做有版本的迁移；旧记录新字段为`null/unknown`，不能追填并声称当时已检测到。可选调试导出失败与主报告保存失败分开处理；后者仍按第6节保护未保存结果。

### 14.2 建立一个小型固定回归集，而不是本周训练模型

最小集先覆盖：正常两项动作、部分起立、未回位抬臂、屈肘/侧倾、遮挡、出画、低光、多人、正常弯腰/坐下/床椅卧位、受控低位、切模式与断连。可以少量经同意的自采录像起步；未获得真实视频时用合成骨架测逻辑，但报告必须写清仅为逻辑测试。

每个用例有case_id、输入来源/许可、实际观察、人工标注、预期行为、实际结果。正常动作和困难负样本都保留，不只收集演示成功的视频。人工标注定义先写清：起立完成时刻、完整往返、角度三点、姿态可见性；分歧要注明，不用模型裁决模型自己的测试答案。

同一视频、同一参与者以及相邻窗口保持在同一开发/验收组；最终保留未参与调阈值的新使用者或新录制条件。同一个人的另一条录像不是跨人验证。先按人划分再切窗口；缩放/镜像增强也留在原组。少量用例只构成工程测试，不称临床验证。

### 新增输入与切换测试（必须）

### 新增数据/规则回归用例（需Codex实现，不是随包已完成测试）

- `schema_id/关节顺序`不匹配时拒绝分析；17点外部骨架不经映射不得直接进入COCO17几何函数。
- 只有腕点失效时，必要条件仍满足的肩抬举角可保留；屈肘问题为无法评价，不误播纠错。
- 同一次动作可同时标屈肘与侧倾；目标未设置时不产生未达标；遮挡不变成“动作控制差”。
- 膝点缺失返回null；原图与局部归一化轨迹同时保留，整体下降不能被逐帧居中抹掉。
- 改变回放播放速度不改变已处理同一时间序列的任务时长；显示回放的帧跳过需报告有效覆盖。
- 在线时序只用过去和当前点；新增未来帧不得改变过去已输出的报警时间。
- 数据保存许可关闭时没有原始视频/逐帧骨架落盘；隐私暂停后没有新数据导出。
- 标注与预测分离；同一参与者/录像/窗口不会同时进开发和最终验收组。
- 无Sports2D、STGCN-rehab、数据集或CUDA也能启动主程序与CPU检查；缺可选资源不报主启动错误。

### 分层记录指标，不用一个“总体准确率”

| 层 | 要记录 | 不能替代什么 |
|---|---|---|
| 关键点 | 指定帧人工参考误差、缺失率、必要点有效比例 | 高置信不代表位置准确 |
| 投影测角 | MAE、平均偏差、重复测量差异；说明机位与选帧 | 不代表三维解剖关节验证 |
| 计数/分期 | 每组绝对误差、部分动作误计、起止时间误差 | 计数对不说明幅度和质量对 |
| 质量规则 | 每种问题分别precision/recall/F1，另报无法评价率 | 不只报样本多数的“正常”准确率 |
| 安全事件 | 事件级召回、每小时误报、实际触发延迟、有效观察覆盖 | 不用帧准确率声称真实跌倒预测 |
| 整套应用 | 有效完成/拒测、断连恢复、切换、保存、重开、持续运行 | 单元测试不是摄像头现场通过 |

有人工二维参考时可用Kinovea测量；Sports2D只能辅助发现定义/代码差异，不能自封金标准。[R3,R4] 测角报告必须包含失效比例；只在最清楚的成功帧测MAE会掩盖使用问题。安全误报同时报告总测试时长与实际有效监测时长，未启用的三个场景不计入覆盖时长。

首周少量样本不适合宣称已达到统一临床阈值。先固定人工标注规则和验收用例，再调参数；每次提交同样回归集的变化与新增失败情况，保留上一可用版本可回退。建议至少完成一轮30分钟连续运行，以及“评估→活动→卧室→安全→评估”往返和保存/重开实测；时间是工程验收建议，不是医疗可靠性证明。

## 17. 后续再扩展

只有当前单路产品完成后再考虑`../plans/FUTURE_EXTENSIONS.md`。研究模型和数据详见`../plans/RESOURCES_AND_UPGRADES.md`，是选型备忘，不是首周安装清单。

改进按证据分流：骨架正确但计数/阈值错→修改状态机与规则；骨架正确但质量规则难以泛化→之后训练小型多标签质量判断层；关节点持续定位错→先改善机位/衣着/照明并留困难样本，仍失败才比较或微调姿态前端。规则调整不是神经网络微调。

REHAB24-6含RGB、骨架及动作分段/正确性标签，可用于获许可后的独立研究；其动作清单有肩外展但没有坐站，正确/错误标签不能直接变成“屈肘/侧倾”的逐问题标签。作者限制非商业研究，商业用途需另行联系；不能因本项目叫Demo就自动绕过。[R7] 本周不下载数据集、不设训练命令或epoch指标。

若后续训练：以人工可见问题作多标签输出，保持采集有效性独立；按人/录制分组隔离，训练期拟合归一化参数，不用测试数据调参。新模型须与冻结规则基线在独立数据上比较，并检查原来正常动作是否退化；开发环境通过不自动替换线上权重。

多路版届时需要每路独立跟踪/调度及持续安全监测；当前单路切模式不承担这些尚未实现的后台职责。

# 手机运动与蓝牙心率（APK 0.3.4）

## 使用入口

安装 `android_offline/dist/tele-rehabilitation-mobile-0.3.4.apk`，包名及原证书不变，可以覆盖升级。手机首页长按右上角头像，进入原生“手机与云端”菜单，选择“运动与心率”。如果当前是 TEST 林女士，先在同一个菜单选择“返回个人档案”。本轮不修改主页面布局、图标、配色或原康复流程。

未连接手环也能开始记录。随身携带手机，授权“身体活动”；室外步行或跑步时，可额外勾选 GPS 并授权精确位置。允许通知，方便从通知栏查看状态和结束记录。结束后在该入口查看“运动记录”或“今天汇总”。GPS 原始经纬度保存在记录中，可通过系统文件选择器导出 JSON；暂时没有地图轨迹页面。定位、步数、心率不自动上传、不进入家庭共享。

日常计步可不勾 GPS，以减少耗电。需要记录时由本人点击开始，通知栏持续显示；最长一段 24 小时或 60000 个保存样本，到限后停止，之后可再次开始。不能把“当日已记录”当作全天完整数据。系统强制停止、重启、撤销权限或节电限制可能中断采集，需要本人重新开始；不会隐蔽自启动或自动补齐记录。先开始后切屏的前台服务不申请永久后台定位，不改变原有小米运动健康绑定。

## 可以测试的功能

| 功能 | 本轮实现 | 数据边界 |
| --- | --- | --- |
| 手机计步 | TYPE_STEP_COUNTER、实际增量、覆盖时长、当天汇总 | 不是手环历史步数；首次样本仅建立起点，未采集时间不补数 |
| 户外运动 | GPS、距离、当前速度、配速、时长、经纬度记录 | 手机必须随身携带；室内和低精度定位可能暂不出路程 |
| 实时心率 | 手选 BLE 设备、GATT 服务发现、CCCD 订阅、实时显示 | 必须开放标准 180D/2A37 通知；本轮未验证小米手环7真机 |
| 运动心率记录 | 最多每5秒保存一条有效心率；已保存样本的均值/最小/最大 | 不是静息心率、全天平均、医疗心电或心律诊断 |
| 故障恢复 | GATT 连接超时、有限重连、过期值清空、采集独立运行 | 无心率不阻断手机计步/GPS；后台保活仍待红米实测 |
| 本机历史 | 独立 SQLite、按本人和自然日查询、重开读取、单次导出 | 与原手填健康指标和 TEST 档案分开；原文字备份不含这份运动库 |

睡眠、血氧、手环历史运动和历史心率不通过标准心率广播获得。本轮没有伪装成已获批厂商接口，也没有安装未经授权的第三方绑定组件。上一期厂商云历史后台保持默认关闭。

## 数据流与计算

原 PhoneStore 的实际 owner UUID → Android 原生 owner 绑定 → 本人明确开始 → 权限/可用性检查 → 非导出前台服务 → 手机计步/GPS + 可选 BLE → 独立本机数据库 → 原生状态/历史/今天汇总。

1. 计步：`Δn = C(t₂) - C(t₁)`。C 是手机计步传感器累计数，不把开机以来累计数导入。重置、非法值、旧时间戳、异常跳变仅建立新起点。跨自然日的第一段不分摊未知步数；下一段继续。注册前缓存事件不计入本次。
2. GPS：对准确度≤25米、时间有效的点，使用 Haversine 球面距离；`v = d / Δt`，`pace = 1000 / v`（秒/公里）。大于30秒的断段不连线；超过12 m/s的跳点排除，小幅定位抖动不累计。25米、12 m/s、30秒是可调整的步行/跑步工程过滤参数，不是临床金标准，也未宣称实机距离准确率。
3. BLE：仅检查标准心率服务180D、测量2A37及通知描述符2902。按 Flags 解8/16位心率、佩戴接触信息、可选累计能量和RR间隔；RR单位换算为秒。无接触、截断和非法报文不成为读数。不写私有认证指令、不重置能量或设备、不改绑定。
4. 时效：标准广播不提供测量时间戳，记录手机接收墙钟及单调时间。15秒没有新心率即清空实时数；断连立即清空。GPS速度20秒没有新有效定位即不再显示。历史保留此前有效样本，但不插值或沿用旧值装成实时读数。
5. 保存：`phone-motion-v1.db`，SQLite schema2；sessions 记录本人/采集范围/明确终止状态，samples 保留顺序号/原始JSON/来源/接收时间/自然日及数值聚合列。schema1升级只增列并从原样本回填，不改原JSON。汇总用SQL聚合，导出在后台准备，避免在主线程解析大量报文。切换本人或恢复备份会先停旧采集，结束原因记录为 owner_changed；异常退出不改成“已完成”。

本机只读接口：`GET /api/device-motion` → `{available, source, current, today, records}`，来自 `OfflineAndroid.motionRead(当前owner)`。拒绝带owner查询参数和跨域路径。TEST档案/非本人/没有Android桥时 available=false。接口不会创建健康事实、用药记录、训练完成或改变剂量；也未接原康复处方的心率调剂量规则。

## 小米手环7稍后怎么试

1. 先用手机单独记录：带手机室外走2—3分钟，结束，查看记录。步数可能延迟更新；GPS需等待卫星定位。
2. 保留小米运动健康的原绑定。若手环或App里有心率广播开关，打开它，再从“选择心率设备”选手环。Android 12+允许附近设备；Android 10/11扫描还需定位授权。
3. 开始记录、看“当前状态”。出现心率数值才算真的收到广播；“设备未开放标准心率广播”说明当前这台设备没有开放本项目需要的服务，不用恢复出厂。扫描到了设备也不等于接入成功。
4. 连不上时回报：红米系统版本、小米运动健康版本、手环固件、是否找到广播开关、界面具体提示及截图。不要发账号密码/密钥。未验证具体固件能否广播，不承诺Band7必然兼容。

## 依据

- [Android计步传感器](https://developer.android.com/develop/sensors-and-location/sensors/sensors_motion)：累计计数、注册及身体活动授权。
- [Android蓝牙权限](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)：附近设备、旧系统定位授权。
- [Android前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)：health/location/connectedDevice及对应权限；本项目目标API35。
- [Bluetooth Heart Rate Service](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/HRS_v1.0/out/en/index-en.html)：通知格式、接触信息、RR和无时间戳边界。

这些是平台/协议实现依据，不是小米手环7实机兼容、GPS精度或临床效果的验收证据。具体测试分母见 [本轮验证](../validation/PHONE_MOTION_BLE_2026-10-13.md)。

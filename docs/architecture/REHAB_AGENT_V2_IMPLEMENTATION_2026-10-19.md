## 产品目标

- 用户入口：自然语言 + 可选快捷提问；不是让用户操作内部的“本地候选计划”筛选器。
- 引导：优先读取已授权、可信且必要的信息；缺信息时提出一两个关键问题，不使用固定长问卷、不重复问已知条件。
- 编排：语义理解→任务分流→有状态的工具编排→候选草案→程序规则校验→专业审核→用户确认→持久化执行与反馈。
- 人机界面：**内部事件、推理请求、工具参数、JSON、重试、任务状态与审计记录不自动变成聊天消息**。用户仅看到简洁回复、关键追问、必要的风险提示、草案和选择、真正成功或失败的回执。
- 审核原则：AI 草案与规则校验均不是临床批准；由有权限的专业人员审核后，用户才能确认采用。用户补充导致草案实质改变时，原批准失效。
- 默认禁用尚未闭环的功能；不修改真实患者资料，不在此阶段合并 main。

## 新增验收项（77 项以外，独立编号）

- UX01：首次进入时提供可忽略的快捷问题；不限制自由提问。
- UX02：任务缺必要信息时仅问优先级最高的 1–2 个问题；用户回答后推进状态。
- UX03：能使用已授权的既有可靠记录免重复追问；无权限不读取，不推断缺失字段。
- UX04：新条件（如无弹力带）会修改草案条件，标记版本并在必要时撤销旧审核。
- UX05：用户取消、换话题、超时、权限变更或安全升级，旧待确认操作失效。
- UX06：普通闲聊、健康知识、康复指导和计划制定各有适当交互，不强制走计划生成。
- UX07：聊天不得逐条暴露内部工具调用、JSON、推理或重复进度；工具失败仅给用户可理解的说明及下一步。
- UX08：生成待审核草案仅提供“调整草案/提交审核”，不得出现“立即执行”。
- UX09：已获批准的特定版本经用户确认才可执行；必须重新读取后证明持久化和动作可执行。
- UX10：审核退回、候选无匹配、资料缺失时主动询问或说明阻断，不虚构审批或保存成功。
- UX11：紧急危险信号优先处理，阻断后续训练/修改，并保留来源、必要风险信息。
- UX12：对同一个合成患者完成“用户自然语言→主动追问→实际检索→结构化草案→程序验证→专业审核→用户确认→持久化→患者端重开”全流程，并留审计证据。

1. 冻结基础测试与错误用例；检查分支最新代码，而非按旧报告盲目重修。已发现 `workflow.ts` 的 `parseRehabToolSelection` 具有缺失 query 的确定性补全，需真实复测才可改变旧节点状态。
2. 先补可信数据契约、Agent 状态机和安全追问，不把个人记录未经授权交给云端模型。
3. 再完成结构化候选、校验及带版本的专业审核，保证回退与拒绝。
4. 补计划创建/采用、真实动作映射、持久化和 UI 表现。
5. 最后优化语言呈现与跨端兼容，保留内部审计与用户对话隔离。
6. 全量复测原 77 + UX01–UX12。任一关键步骤尚无真实证据即维持 FAIL/PARTIAL/UNVERIFIED，不合并主分支。

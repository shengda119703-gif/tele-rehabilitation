# 康复管家回复协议

协议 `rehab-dialogue-2`，云服务0.3.7；保留原界面、账号隔离、资料授权、测量算法和计量入口。提示词与服务端校验在 `cloud_service/assistant_dialogue.py`，拼装及冻结逻辑在 `cloud_service/assistant.py`。

## 用户会看到什么

- 身体不适：先简短回应，再问至多三个关键问题；结合最近回答补问，不从头重复问卷。腰背痛先了解发生经过、位置、程度、腿部及大小便伴随情况。
- 动作做法：按现有动作资料讲准备、步骤与停止条件，没有资料则先问动作名称，不编动作或新剂量。
- 评估解读：说明已保存结果；定量读数由服务器从授权记录附上，模型不产生角度或恢复率。
- 今天练什么：结合本人已采用方案说明下一步；没有授权或方案时，仅指出相关缺项，不在每条回复前重复整段授权说明。

输出是普通分段文字：一句回应 → “先确认” → 必要的一般措施或“下一步”。症状问询阶段不推荐未经核验的动作或训练剂量。不会再把 Markdown 的双星号直接显示给用户，也不再给腰疼问题附上固定的肩部恢复说明。

## 硬约束

模型只返回以下JSON对象；系统提示词、每轮冻结协议和官方JSON模式共同约束输出。

```json
{
  "reply": "一两句直接回应",
  "questions": ["至多三个需要本人回答的问题"],
  "advice": [],
  "next_step": "接下来怎么衔接，不声称已经执行"
}
```

正文目标120–280字，服务端还有字段长度、列表数量和总长限制。症状模式 `advice` 必须为空，一般性暂停提示可放在开头；疼痛评分允许使用固定的0–10分问询句，不把问询当作测量。模型仍不能输出新测量、确定诊断、药物调整、训练处方、外链或已经执行操作的承诺。

格式、长度或内容校验不通过时，本轮用简短本地问询接住，不再次请求模型；已经发生的供应商Token和费用仍正常保留。回复来源标为本地，不把本地接住的文字称为DeepSeek原答。

## 连续追问与数据边界

每轮带入同账号近期对话和有限原文摘要。开启健康资料使用后才读取本人已同步资料；撤销后不把此前包含授权健康资料的历史转发给模型。近期问答只是对话，不自动变成健康问题、评估值、训练完成或用药记录。

0.3.7增加“本人已回答疼痛评分”的对话标记，过滤重复的评分问题，并更换后续轮次的示例；病情自述加重时可以重新询问。该标记不保存新的数值或临床事件。目前只对这一评分问题加了确定性去重，其他信息主要依靠近期对话与提示约束，不能称为完整结构化问诊状态机。

每轮保存协议版本、冻结提示词和原操作编号。重试使用原提示词，不在更新后悄悄重写旧问题、重建旧读数或重复计费；旧版未完成请求继续使用旧解释规则。

## 危险症状

腰背痛伴明确自述的新发排尿困难、大小便失控、会阴麻木或双腿明显无力等，走固定的及时急诊提示，不等待付费模型，也不推荐先做动作测试。否认、假设、过往或一般概念提问不直接当作当前危险症状。该文字规则只是保守的工程分流，不能排除急症，也未完成临床验证；其他表达或其他疾病并不保证被完整识别。

措辞依据：[NHS腰背痛就医提示](https://www.nhs.uk/conditions/back-pain/)，页面复核日期2026-03-05，本轮核对2026-10-15。JSON模式依据：[DeepSeek官方JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。未引入自动诊断、开药或临床处方引擎。

## 验收

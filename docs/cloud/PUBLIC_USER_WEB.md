## 实现与隔离

1. `cloud_service/browser.py`复用现有服务、Cookie登录和患者权限；完整产品HTML只提供给当前WEB患者会话。HTML只注入本人公开账号身份，不注入访问令牌、刷新令牌或密码。
2. `public_web/browser-account.js`在原本地适配器初始化前选择`ankang-phone-cloud-1:<patient_id>`，校验`/auth/me`并只将CSRF值保留在内存。跨账号或另一标签页切换使旧界面停止并重新登录；上传前再次核对云身份。
3. 原`PhoneStore`、`ProductService`、`PhoneMotion`和UI继续使用，未迁移或冒领旧本机／林女士资料。个人来源为`WEB_LOCAL`／`REPLAY_FILE`；跟练仍为`SELF_REPORT`。零值和缺测不补数，服务器来源仍为客户端声明，而不是医疗核验。
4. 云接口仍负责账号、授权和追加结果，数据库schema1不变。本次没有部署Python模型推理、原`PhoneHost`公共API、帧上传或原片上传；不存在无患者边界的全局视频目录。
5. 只发布显式资源清单中的62个公开资源和两页HTML，SHA逐项验证；服务器拒绝未知清单或篡改。MediaPipe／OCR资源来自已校验的原Android资源，不包括私人数据、密钥、虚拟环境、录像、林女士夹具或fitness-demo。
6. Worker、WASM和本地视频所需CSP只对完整产品页开放`blob:`与`wasm-unsafe-eval`；账号／医生页面继续原严格策略。保持正常HTTPS、HttpOnly／SameSite Cookie、CSRF、登录限流、同事务审计和医生授权边界。

# 登录账号下的家人关联

2026-10-15，云服务0.3.8/schema5、Android0.5.8/code58。沿用原家庭页面、按钮与分类共享方式，不新增家庭成员角色或替换旧设备备份服务。

## 使用

双方登录各自账号。一方在“家人 → 我的邀请码”生成8位码，另一方在“关联家人”输入。码有效15分钟、一次性使用，重新生成使旧码失效。输入有效邀请码立即建立双方关系；系统不验证法律上的亲属关系。

关联后健康、康复和用药三个类别均默认关闭。双方分别决定“我共享给TA”的类别，不能替对方授权。健康指标还必须由本人单独标为`family_ok`。已有联系人字段不等于已关联账号。

## 接口和数据流

所有新接口均在`/api/cloud/v1/patients/{本人patient_id}/family`：

| 方法与后缀 | 用途 |
| --- | --- |
| GET 无后缀 | 返回双方关系、本人授出的类别和对方允许的有限摘要 |
| POST `/invite` | 生成本人邀请码；数据库只保存哈希 |
| POST `/bind` | 消费另一人的邀请码，不接受直接指定其他账号代绑定 |
| POST `/grant` | 仅修改本人授出的类别 |
| POST `/unbind` | 解除双方关系并撤销双方分类授权 |
| PUT `/summary` | 发布本人已授权类别的有限摘要，不接受聊天或原件字段 |

Android的`PhoneCloud`家庭请求改经`PhoneAccount`与原生`AccountTransport`；网页改经同源Cookie/CSRF通道。患者ID从当前登录身份确定，不从UI传入任意服务地址。云账号档案不能退回到旧设备连接码身份；未绑定云账号的旧设备档案保留原通道。旧云备份通道保持独立。

家庭页每次读取／刷新都重新核验服务器关系和权限，网络失败时不把旧缓存作为新授权；后台读取也不能覆盖较新的分类变更。摘要上传失败不撤销已成功保存的关系或授权回执。

## 保护与范围

- 仅本人患者账号可管理其家庭资料。医生资料授权不提供家庭关系读取权；家属关系不提供完整患者记录、报告原件或管家对话读取权。
- 三张新增表：`account_family_invites`、`account_family_links`、`account_family_summaries`。schema4到5为增量建表，不搬移或改写原临床记录、账号、模型配置及计费。
- 邀请生成与输入均有按账号限流；最多10位关联家人。并发关联串行消费邀请码，同一接收方丢失回执后的重试可以恢复原关系，第三人不能复用。解除后原已消费码不能重新建立关系。
- 摘要输入每类最多10条、读取每类最多5条；只有已授出类别才入库和返回。撤销最后一个对应类别授权会清理该类别缓存，不会在重新授权时自动复活旧摘要。
- 摘要由本人客户端在读取或更改权限时发布，不是实时监控，不新增临床测量、处方、服药确认、视频通话或完整健康档案同步。
- 独立报告分享仍按原分享码管理，解除家庭关联不自动撤销独立报告链接。

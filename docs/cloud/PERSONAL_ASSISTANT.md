# 个人康复管家与统一模型网关

当前版本：电脑0.25.6、Android0.5.7、云服务0.3.7 / schema4。沿用现有界面，不改测角、计次、机位、训练质量、疼痛反馈及真实记录保存算法。新增分场景的短回复和症状追问，协议与限制见[回复协议](ASSISTANT_DIALOGUE_PROTOCOL.md)。

## 使用入口

- 医疗工作台：`https://139.224.216.18/care`。共用医生账号登录后，右上角“智能服务”配置 DeepSeek；“用量汇总”查看所有普通账号的运营计量。密码沿用现有设置，不写入源码或本文。
- 用户：网页登录或新版 APK 登录本人云账号，打开“康复管家”。“使用说明”内可设置“允许管家使用我的云端康复资料”和“康复目标与条件”。资料使用、记录自动上传、医生共享是三份独立授权，不能相互替代。
- 同账号在另一端打开管家可同步已保存对话；“本次不记录”和私密表达仅在当前客户端处理，不发送到云端对话接口或模型。
- 只读取已经同步的本人资料；尚在某台设备的本地资料，必须先按原“联系康复医师 → 资料与授权”流程确认归属与上传。不会偷偷扫描或上传其他本地档案。

## 管家如何协作

1. 账号认证后，服务器按本人 `patient_id` 读取偏好、对话及目标，不接受模型指定其他患者。
2. 本人开启资料使用后，服务器从最新记录视图读取健康资料、目标、限制、评估、训练感受及本人已采用的医生安排；问肩部时优先相关项目。合成/展示资料不作为本人实测依据。
3. 采用现有版本化动作资料库、动作出处与规则。文字资料卡可被解释，不代表其全部具备自动测量能力；实际执行仍以原 53 项测量契约及设备端校验为准。
4. DeepSeek负责一般问答、症状资料问询和文字解释，按服务端JSON协议输出短回复与至多三个追问。数值、完成次数、疼痛/疲劳及安排来自保存的原记录，由确定性代码展示；问询回答只保存在对话里，模型不能写入测量结果、诊断或改药。
5. 后端提供允许的“打开本人评估”“查看训练安排”“联系医师”“提交候选”入口。导航不自动开启摄像头。候选须本人明确提交，沿用目标、器材、限制、已有评估与医生授权检查。
6. 医生在患者信息中展开“候选方案审核”，核对资料和来源。审核不会发布处方；医生另在正式方案编辑器选择已支持动作、填剂量并发布，患者仍须在原客户端核对评估并采用，才能按原训练流程执行。
7. 后续提问重新读取已同步结果及实际反馈，不由聊天偷偷修改处方、负重、次数、药物或原历史。尚需临床判断的调整继续交给医生。

历史摘要是有版本的有限原文摘录 `DIALOGUE_EXCERPT`，不是训练出的长期临床记忆或新增诊断；完整对话另行分页保存。允许的数据范围、上下文记录版本和采用方案版本随每轮保存。重试使用原冻结请求及原操作号，避免二次付费；授权变化时不重发旧健康上下文。

## 密钥与调用

所有正常产品调用统一经账号网关。手机不内置共用密钥，也不再使用旧版原生个人密钥旁路；电脑产品聊天同样经账号服务。未登录、私密及离线回复走本地路径。服务器不会向模型传报告原件、录像、家庭其他成员资料或设备令牌。

管理员在“智能服务”填写 API Key，保存后可校验官方模型列表。密钥不回显、不进入页面存储、源码、APK、Git 或测试证据，保存在服务器专用目录 `/var/lib/ankang-cloud/ai/`：目录 0700、文件 0600、服务账号拥有，原子写入。它是操作系统权限保护，不宣称磁盘加密。修改立即生效，切换发布目录不丢配置。

模型列表校验不消耗问答 Token，也不等于真实问答已验证；只有成功问答回执才标记 `CHAT_VERIFIED`。未配置密钥时可使用真实已保存资料的本地解释，不伪称 DeepSeek 已回复。密钥不能通过聊天或文档交接。

## 用量与预算

`patient_ai_receipts` 保留真实供应商回执；`patient_ai_request_labels` 保存用途。输入、输出、缓存命中/未命中及合计来自 `usage`，不按文字长度冒充计量。文字字节数仅用于保守预留额度，界面与实耗分开。

按北京时间提供每日、每月、每用途明细、模型、状态、时间、剩余次数和 Token；医生可调整每用户月额度。未知或超时用量标为待核对、保留预留，不伪称免费，也不会自动重复付费调用。账单/用量入口不暴露患者 AI 对话正文；医生健康资料共享不代表获得私密管家对话授权。

“智能服务 → 计价单价”可填写当次核对的版本、币种及每百万 Token 的三项单价。每次回执冻结价格；切换模型不沿用另一模型的价格。官方存在不同时段价格，手工快照不是自动节假日/时段账单系统，费用需与供应商账单核对。未填价格显示未计价，不补造金额。

## 核心接口

| 接口（前缀 `/api/cloud/v1`） | 作用 |
| --- | --- |
| `GET/PUT /care/ai/settings` | 管理员配置；返回状态，不返回密钥 |
| `POST /care/ai/check` | 已配置密钥的模型列表检查 |
| `GET/PUT /patients/{id}/assistant/preferences` | 本人资料使用授权，版本检查 |
| `GET /patients/{id}/assistant/conversation` | 本人跨端对话、摘要及递增游标 |
| `POST /patients/{id}/assistant/turns` | 本人原问题、稳定操作号、冻结上下文与统一计量 |
| `GET /patients/{id}/ai/usage` | 月、日、用途及会计回执，不含对话正文 |
| `GET /care/ai/usage` | 管理员按月运营汇总，不含病历/对话 |
| `PUT /patients/{id}/ai/budget` | 管理员设置本人账号月预算 |

账号会话、CSRF、本人范围、原医师授权、不可变事实和草稿/发布/采用版本检查保持。schema 4 仅增加辅助表；发布先加密备份并在恢复副本验证迁移及旧版本回退，不用旧数据库覆盖现有患者历史。

官方接口核对： [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。2026-10-15 核对模型名及默认思考模式；网关使用非思考模式，控制普通解释的等待与输出预算。

# 手机功能增补：体态、实时指导与跨设备协作

更新：2026-10-03。本轮不改桌面康复测量契约，不处理动作图片。手机网页继续由电脑提供服务。

## 已接入的操作

| 入口 | 操作与结果 |
| --- | --- |
| 身体评估 → 站姿体态评估 | 正面 / 侧面录像，逐项返回肩线、髋线、躯干倾角、耳肩水平偏移和膝部投影夹角；可以重开、回看和打印 PDF |
| 身体评估 → 选择动作 → 打开实时动作指导 | 浏览器授权相机，将压缩帧发到电脑；复用原 53 项动作的模型、测量、计次及下一步指令；默认前摄镜像，可选语音，停止 / 切页 / 锁屏时释放相机 |
| 身体评估 → 身体汇总 | 汇总最近评估、训练次数和训练反馈，查看上一项、继续计划或提示先休息 |
| 训练中心 | 本轮完成后可确认当前适用条件，生成下一轮基础活动安排；仍用原规则，不自动加量或绕过不适记录 |
| 设备连接 → 在另一台设备继续 | 原设备生成10分钟一次性档案连接码，新设备先连接本机服务，再输入档案连接码。切换身份，不合并或删除原档案 |
| 身体汇总 → 报告与随访 | 显式确认后创建7天只读摘要链接；不包含录像；持链接者可留言，用户可随时撤销。身份未核验的留言不自动改训练计划 |
| 设备连接 → 网络摄像头 | 读取电脑端批准的 RTSP 机位，测试当前画面，选择动作录制5–60秒，随后进入原分析队列 |

跨设备指**手机与电脑浏览器共用网页档案**，不是自动合并 PySide6 患者数据库；还没有注册登录、遗失恢复、机构角色与医生身份认证。分享链接当前要求对方能访问同一台服务主机，局域网地址不能发给外网直接访问。

## 算法与数据边界

### 体态

`posture-projection-1` 复用已有 YOLO COCO17。按所选视角、侧别，逐指标检验必要点置信度、像素范围和线段长度。跟踪最初主要参与者，不在其离开时改用旁人。每项要求连续观察窗口至少2秒、10个有效样本；使用中位数汇总，并记录中位绝对偏差、有效样本和覆盖率。这些是工程取样规则，不是临床正常值。

正面肩线 / 髋线与画面水平比较；躯干与画面竖直比较；侧面耳肩偏移以肩髋投影长度归一化。后者不区分前后方向，不命名为头前伸诊断或颅椎角。缺测返回 null；无关关节缺测不清零其他指标。摄像头倾斜、透视、衣着、主动摆姿仍可改变数值，未自动判断机位。

**骨盆前倾、圆肩诊断、脊柱侧弯、C7 / 髂前上棘 / 髂后上棘识别尚未实现。**髋中心不是骨盆精细表面标志点。模型点位参考：[MediaPipe 官方点位说明](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/PoseLandmark)；不能把模型预测的相对三维坐标当作已标定多摄像头重建。

### 实时指导

每次只有一个活动实时指导进程；浏览器逐帧等待应答，不积压视频；画面最大1280像素 / 512KB，单次10分钟，断开30秒退出，单帧25秒超时终止。画面仅在内存中，不保存录像或把实时练习计入评估库。动作支持取决于本机原关键点组件；没有重新训练模型。实时角度、计次和大字提示复用 `PoseAnalyzer`、`RehabEngine`、`GuidancePolicy`，不降低原缺测 / 时间间隔规则。前摄镜像仅显示，不镜像原图坐标。

手机访问普通 `http://局域网IP` 无法授权 `getUserMedia`，页面提供明确回退；用已受手机信任的 HTTPS 地址后才可实时使用。参见 [MDN 相机安全上下文要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。本地 `localhost` 是浏览器特例，不代表手机的 HTTP IP 地址也能工作。原系统相机录像上传继续可用。

### 训练与随访

本轮补齐反馈到下一步、身体摘要、分享与完成后续轮入口，没有修改 `general-activity-rules-1`。继续检查评估日期、有效片段、本人完成次数和不适记录；没有把体态 / 健身结果混入康复计划。疾病 / 术后方案、自动长期加量仍待专业方案和验证。留言是未经身份核验的沟通记录，不是已执行处方。

## 网络摄像头配置

在电脑 `.runtime/mobile/network-cameras.json` 写入以下格式；此目录已忽略，含密码的配置不得上传：

```json
[
  {"id":"front","name":"正面机位","url":"rtsp://用户名:密码@192.168.1.100:554/厂家提供的流路径"}
]
```

请用厂家真实地址，特殊字符需要 URL 编码。只接受 RFC1918 局域网字面 IPv4，不接受任意公网地址、域名、回环地址、云元数据地址或网页提交的任意 URL。网页只拿到机位编号和名称，不拿到流地址和密码。没有自动扫描局域网，也没有 ONVIF 发现 / 云账号登录。

测试画面只取一帧；不是持续直播。录制使用独立 FFmpeg 子进程、无音频、H.264，结束后离线分析。录像按15fps重采样，`capture_source=NETWORK_CAMERA` 与 `capture_timebase=ffmpeg_resampled_15fps` 保存在任务中，分析仍标记 `REPLAY_FILE`；不是曝光级同步或双机三维融合。摄像头尚未购买，实际协议兼容、断流和时间精度尚未验收。

新增依赖 `imageio-ffmpeg==0.6.0`，来自 PyPI 官方包，仅作为 FFmpeg 可执行文件来源，不更换姿态依赖。[上游项目](https://github.com/imageio/imageio-ffmpeg)包装器为 BSD-2-Clause，附带 FFmpeg 的构建许可另行适用。本机二进制 FFmpeg 7.1，SHA256 `2CE797A0F88D7F067180338FB227F7B1928EA727BD9A4D7A1D022F7C52AF71A3`；正式分发需随附并核对二进制许可证。

## HTTPS 与容器部署

交付配置位于 `deploy/mobile/`：Dockerfile、CPU 推理依赖、Compose 和 Caddy HTTPS 反向代理。只部署网页分析服务，不在镜像安装桌面 Qt。模型只读挂载，本地运行数据和密钥不打入镜像。单分析队列 + 单实时进程，不能开启多个 Uvicorn worker 共享同一数据目录。

Linux/AMD64 主机操作：

1. 获取代码及合法持有的原模型文件和匹配的 `manifest.json`，放回 `rehab_codex_single_camera_v2_1/assets/models/`。容器不会在启动时下载模型。
2. 将域名解析到自己的主机，放通80/443，不把8765直接开放公网。设置 `REHAB_DOMAIN` 为该真实域名。
3. `docker compose -f deploy/mobile/compose.yaml config` 核对后，执行 `docker compose -f deploy/mobile/compose.yaml up -d --build`。
4. 在主机日志中读取连接码。域名和网络条件满足时，Caddy自动申请证书；打开该 HTTPS 地址。
5. 备份 `mobile_data` 卷，保护连接码、分享码、原始录像和个人数据。撤销分享不删除原记录。

容器基线只包含 YOLO 动作；腕 / 踝 / 手指的可选隔离环境没有打入 Linux 镜像，不把本机可用性当作云端已支持。`REHAB_TRUST_PROXY=1` 只在 Compose 内网代理下使用，不能用于直连公网的8765。`REHAB_ALLOWED_HOSTS` 限定 Host 名称。

也可不用容器，启动参数 `--ssl-certfile 可信证书.pem --ssl-keyfile 私钥.pem` 提供直接 HTTPS。证书须包含实际域名 / IP 并由手机信任；不要关闭证书检查。程序不会安装根证书或修改系统信任。

[Caddy HTTPS 条件](https://caddyserver.com/docs/automatic-https)。本机 Compose 配置校验通过，但 Docker 引擎未启动，**未构建或运行镜像，未创建阿里云资源，未验收公网部署**。公开使用前仍需正式账户与撤销会话、访问审计、备份恢复、渗透测试和合规检查；当前配置是受控演示起点，不是生产医疗平台。

## 尚不能替代的工作

- 手机实机取流与延迟、全部动作真人对照、网络摄像头硬件验收。
- 同步标定双摄的真正三维融合，以及精细关节 / 体表标志点。
- 肌肉真实发力、肌电、关节力矩、地面反作用力等需要对应传感器或经过验证的生物力学方案；保留现有器械外力 / 功率估算，不改名冒充。
- 原生手机 App、桌面患者库与网页统一账号、正式医生工作台、疾病 / 术后处方和长期自动进阶。
- 图像素材本轮不处理。

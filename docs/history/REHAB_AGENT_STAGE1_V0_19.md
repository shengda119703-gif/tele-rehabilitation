# 康复管家移植第一阶段 · 0.19.0

日期：2026-09-28。目标：用户可以先问今天如何安排，由本机保存记录解释原因，再进入已有康复页面。

## 用户得到的功能

- 原桌面右上角新增“康复管家”，保留已有评估、训练、档案与历史页面。
- “今天该练什么”：每次重新读取当前用户 / 来源 / 情境的评估；没有可用依据时引导先评估。
- “为什么这样安排”：显示现有规则使用的评估次数、保守组次及适用条件，不编造新处方。
- 已有自动计划：查看这轮完成数量与下一项；过期、条件改变、缺反馈、不适及已完成分别解释，不自动加量。
- “我的评估结果”：显示最近各项保存的投影范围和完整动作次数，并可打开身体档案。
- “查看历史记录”：统计保存的评估 / 训练条数，不把记录数说成有效训练次数，不自行下康复改善结论。
- 明确拒绝训练时不推荐操作；提到疼痛等信息时说明尚不能判断否定、过去或当前语境，不写入症状和诊断。

## 与安康 Agent 的关系

参考 `JerryFreeman333/fdu-hackthon` 本地检查版本 `5df927143e72e650476ef2bb32f776d5ff3329fc` 的
`src/agent-tools/intentRouter.ts` 和 `src/engine/agent.ts`：意图路由、条件优先、结构化工具结果与表现层分开。
本阶段在 Python 中适配上述结构，没有整包复制 React 页面，也没有迁入完整理解层、Person Twin、事件流、LLM Adapter 或语音。

`app/rehab_agent.py` 是有限意图的本地规则版；输入支持 1–500 字。输出包含规则版本、意图、读取时间、证据记录、工具名称和允许的导航操作。
只读真实存储，复用 `build_body_profile`、`generate_proposal`、`program_progress`、`validate_automatic_use`。
这些工具不是联网函数调用；动作名称和数据入口都由程序限定。

## 数据和交互边界

- 每次提问重读记录，按用户、来源、情境隔离；合成及回放始终明示。
- 对话不持久化、不上传；没有新增数据表，也没有修改个人数据库格式。
- 原应用 Runtime 接收 `rehab_agent` 命令；仅在空闲时读取。训练、预览、连接、相机测试、保存失败时拒绝进入，避免分析大批记录占用实时采集。
- 请求编号、对话范围、当前用户共同过滤迟到回复；新问题或失败清空旧操作。
- 计划按钮只打开原自动安排页面。适用确认不预勾选，实际计划生成 / 保存 / 准备和摄像头仍受原规则控制。
- 管家不会打开或停止摄像头、填写疼痛评分、发送家庭通知或启动训练。
- “今天”是询问入口，已有计划显示“这轮”；不把跨日保存计划冒充今天已完成的活动。

## 当前限制与下一阶段

第一阶段完成的是入口、读取、解释和跳转。它不是完整安康 Agent 的移植，也不代表临床有效性或所有真实口语都能正确理解。

第二阶段优先：把训练保存事件、用户明确填写的疼痛 / 疲劳与后续步骤接起来；复用原反馈写入和计划安全规则，覆盖中途结束、重复事件、保存失败重试。
之后再移植安康的结构化语言理解与多轮上下文，让否定、历史感受和当前自报能够区分；接入模型时需明确配置和发送数据范围，继续由既有规则决定训练参数。
家庭共享、手机 / Apple 健康数据与语音随后独立验收。

# DeepSeek 康复 Agent · 0.21.0

日期：2026-09-28。

## 用人话说，增加了什么

以前的 0.19 只会认少量关键词，0.20 虽然能接大模型聊天，但模型回答和本机查询结果仍是两块分开的。现在形成了完整闭环：

1. 用户可以像正常聊天一样提问，DeepSeek 理解“那继续吧”“为什么这样安排”等上下文。
2. 如果只是聊天，DeepSeek 直接自然回应。
3. 如果问题涉及训练安排、评估、历史、拒绝训练或当前不适，只允许进入已经列出的本机只读工具。
4. 原康复程序按当前用户、来源和情境读取真实记录，并继续负责安全门槛、计划和页面跳转。
5. DeepSeek 只拿到一段最小化的本机结果文字，再把它解释得更自然；界面同时保留“本机记录与规则核对”原文。

这意味着大模型是“会聊天、会理解、会解释的管家”，不是新的姿态算法，也不是医生，更不能绕过原来的康复逻辑。

## 数据与安全边界

- API Key 只保存在当前进程内存，不写文件、数据库或 Git。
- 服务地址固定为 `https://api.deepseek.com`，避免用户误填第三方地址后泄露 Key。
- 默认模型为 `deepseek-flash`，可改为 `deepseek-v4-pro`；不再使用已经停用的旧模型名。
- 首次调用只发送本轮文字和最近 6 轮明确可分享的对话。
- 查询后的第二次调用只发送本轮问题和本机生成的结果文字；不发送姓名、participant / session ID、原始数据库行、摄像头画面或全部档案。
- “不要记录 / 不要告诉家人”等隐私表达整轮留在本机，也不会进入以后发送的上下文。
- 模型只能选择 `plan / assessment / history / defer / condition` 等受限意图，不能执行摄像头、保存记录、确认计划或发送消息。
- 模型解释不得新增本机结果中不存在的数字；失败时退回第一段回复，本机核对结果仍然可见。

## 模型和本机代码分别负责什么

| 内容 | DeepSeek | 本机康复代码 |
| --- | --- | --- |
| 普通聊天、情绪回应、连续追问 | 负责 | 不负责 |
| 理解用户想查计划 / 评估 / 历史 | 提议意图 | 校验并限制范围 |
| 真实次数、角度、评估和计划 | 不生成 | 唯一事实来源 |
| 是否因不适而暂停、能否继续 | 不自行决定 | 原规则与用户确认负责 |
| 结果说成人话 | 负责 | 原文同时保留 |
| 打开页面或执行训练 | 无直接权限 | 用户点击原有按钮后执行 |

## 仍未完成

开发环境没有用户的真实 DeepSeek API Key，因此没有声称已完成真实联通、实际回答质量、费用和网络延迟验收。当前也没有语音、长期记忆、家庭消息发送、医疗诊断或自动处方。

DeepSeek 接口实现依据官方的 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [模型列表 / 价格](https://api-docs.deepseek.com/quick_start/pricing/) 文档。

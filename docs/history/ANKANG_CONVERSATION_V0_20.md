# 安康对话能力接入 · 0.20.0

日期：2026-09-28。用户验收 0.19.0 后指出：关键词导航不具备原安康的对话体验。按用户确认的 MiniMax 服务接入真实模型通道，仍保留原康复业务规则。

## 本阶段交付

- 连续聊天记录：最近 6 轮可分享文字提供给模型，窗口最多显示 20 轮；可以清空。关闭窗口清空对话，切换用户不会继承聊天内容。
- MiniMax 配置窗口：HTTPS 根地址、模型名、掩码密钥、明确的数据发送授权。配置保留到软件退出，不写数据库、文件或 Git。
- 自由聊天和语义路由：模型输出自然回复、有限查询意图、感受语境。普通聊天不读患者库；“那继续吧”等由模型结合对话理解。
- 查询结果由本地规则单独显示：模型决定查询意图，本机读取评估 / 自动计划 / 历史，实际操作仍需要点击原页面。原始数据库、姓名、参与者编号、病史和评估记录均不作为模型请求上下文。
- 移植隐私过滤：明确“不记录、不上传、别告诉家人”等输入不调用模型，该轮也不会被带入以后发给模型的历史。
- 模型失败、缺少配置、格式错误、超长结果和越界执行声称都有明确状态，不再静默把规则回复冒充真实模型。
- 联网在有界可选工作队列运行。慢回复不占用摄像头调度线程或锁住主界面；关闭聊天可继续操作原软件。实际训练 / 预览期间仍不进入管家。

## 原安康代码与移植对应

参考版本：`JerryFreeman333/fdu-hackthon` 的 `5df927143e72e650476ef2bb32f776d5ff3329fc`。

| 原模块 | 本次适配 |
| --- | --- |
| `engine/agent.ts` 的 Adapter、回复边界、温和回复原则 | Python `agent_conversation.py` 的 MiniMax 请求、结构化返回校验与受限回复 |
| `engine/privacy.ts` | 当前句隐私判定，以及后续上下文逐轮过滤 |

这是对对话能力的 Python 适配，不是 TypeScript 整包执行。未迁入完整症状标签系统、健康事件流、家庭共享、HealthKit、语音和 Person Twin。不能宣称已经完整移植整个安康项目。

## MiniMax 接入与人工验收

用户指定 MiniMax；接口对照 [MiniMax 官方 Chat Completions 文档](https://platform.minimax.cn/docs/api-reference/text-chat-openai) 实现 HTTPS、Bearer、messages、max_completion_tokens、reasoning_split 和 choices 返回解析。拒绝 HTTP 跳转，不向其他地址转发密钥；默认根地址 `https://api.minimax.cn/v1`、可编辑模型 `MiniMax-M3`。用户应填写原安康实际使用且账户可访问的模型 / 地址，不能仅凭默认值保证账户权限。

1. 打开标题为“康复助手 · 0.20.0”的窗口，点击“康复管家”。
2. 点击“连接 MiniMax”，填写原来的 API Key、模型名和地址，确认发送范围，再启用。
3. 输入“我是傻逼吗”，再连续追问；本轮成功时状态显示 MiniMax 和模型名。
4. 输入“今天该练什么”后再问“那继续吧”，核对本机结果和跳转。
5. 输入“不想练”与“不要记录这句话”，核对拒绝与隐私行为。
6. 可用无效密钥验证错误提示；不得显示成功或悄悄退回固定聊天。

未配置时仍明确显示“未连接 MiniMax”。开发时未取得真实密钥，真实在线问答和 MiniMax 账户权限尚未验收；模拟回复截图不是模型效果证据。

## 局限

症状语境由模型解释，但训练导航仍受保守关键词和原计划适用确认约束；例如“不疼”也可能进入确认提示。本阶段未把模型判断写成医学记录，更未允许模型解除医嘱限制或修改剂量。

当前对话仅内存保留，不具备跨重启记忆；康复工具结果不回传模型。因此涉及精细历史统计的问题，模型可能只引导查看本地摘要或历史页，不能承诺回答任意统计查询。

测试证据见 [本阶段验证](../validation/ANKANG_CONVERSATION_2026-09-28.md)。

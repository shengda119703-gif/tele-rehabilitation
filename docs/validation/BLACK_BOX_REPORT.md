# BLACK BOX REPORT · 0.19.2 · 2026-10-07

## 验收范围与结论边界

本轮按用户批准的五页结构重组前端，实际运行 Windows Qt 产品和 Edge 中的统一网页。全部写入使用临时 TEST 档案；没有操作患者档案或真实家庭关系。联网模型没有配置，**不能把本轮称为全部功能验收通过**。已验证的本地健康对话不等于联网大模型对话。

最终运行结果及截图索引在本报告末尾更新。原始证据在本机忽略目录 `qa-output/final-frontend-20261006/`；可复用测试脚本在 `tools/ui-polish/`。本报告不沿用上一版本的测试计数。

## 前端结构与冻结契约

| 页面 | 用户入口 | 沿用的功能与数据 |
|---|---|---|
| 首页 | 今日安排、康复管家、我的记录与周报 | 原日程/逐次服药、原聊天、原 history/report；周报内容来自已有服务 |
| 康复 | 训练 / 评估 / 健身 | 原计划工作区、原评估准备流程、现有网页健身库；实时/录像来源继续区分 |
| 健康 | 我的档案、身体记录、资料与图片 | 原 profile、health.record、archive、图片核对流程 |
| 用药 | 安排、逐次服药、更正历史 | 原 medication/daily 服务；未记录不自动算漏服 |
| 家庭 | 关系、授权、获准近况 | 原家庭业务未改；邀请码不等于手机连接码，不自动共享 |

原生历史控件整体移到首页，原动作 ID、过滤器、报告和康复记录查看器保留。网页增加首页所属的 records 子页。没有改 Runtime、API、数据模型、动作计算、计划生成、权限或医疗语义；不增加周报自动推送。

桌面原本没有与旧 APK 相同的独立健身模块。本轮健身入口明确连接到已有网页工具，连接窗口新增“复制连接码并在电脑浏览器打开”，沿用 PhoneHost，不冒充新增原生健身算法。

## B. UX Black Box

- 实际检查首页记录入口及返回、评估/健身下一步、管理折叠、跨页草稿和数据回看。
- 重新命名“基础模式”为“连接与能力”，展开说明基础健康记录与联网康复查询的可用边界。“查看参考资料”改为“记录与能力说明”；上传原件不会被宣称自动成为模型上下文。
- 检查加载期间禁用、保存反馈、错误反馈、空状态、表单必填/范围、Escape 取消、键盘焦点、减少动态效果、移动端导航与滚动后操作。
- 训练空状态缺少就近评估按钮是在截图中发现的，已增加“去做评估”，保留原评估准备和任务门禁。
- 桌面首次启动在并行测试时超过早期25秒观察窗，改为最多90秒等待实际就绪；不把等待上限当成性能达标。单独首页诊断后实际进程约9秒完成，冷启动体验仍应在目标机器观察。

## C. Screenshot Visual Review

实际 Windows Qt 6.11.2、DPR 1.5；主审 1440×940 浅色、1024×940 深色。Edge 网页覆盖 390×844、320×740、768×1024、1440×940 与390深色。使用完整页面截图，并对长页面补充滚到底部的真实视口截图；固定底栏在 fullPage 截图中处于原视口位置，另用滚动截图检查最终控件可达性。

审查对象：首页、康复训练/评估/健身、健康、用药、家庭、管家、记录与周报，以及原 capture 四工具和档案弹窗。审查构图、比例、密度、字体、对齐、滚动、层级和状态，不以 build 或 overflow 脚本代替观察图片。

| 发现的问题 | 修改与复测 |
|---|---|
| 首页集中在上半部、记录入口分散 | 合并真实周报摘要与记录入口；扩展内容宽度、收窄侧栏；桌面并列今日内容、手机顺序阅读 |
| 表格在隐藏页按过窄宽度计算，显示时行高巨大 | 可见/宽度变化后重新测量行高；实际服药表格、选中与保存截图复查 |
| 网页健康历史只显示通用名称 | 改为已有事件中的真实指标、单位、时间或主诉；用63kg实际跨页验证 |
| 训练文字有评估提示但按钮已移走 | 增加显式“去做评估”，实际点击跳转再返回 |
| 首页第二条日程裁切，增高后与提示重叠 | 让响应布局随内容更新其最小高度；仅对限制高度的区域顶对齐；新增截图时日程与提示不重叠检查 |
| 启动阻止切换提示在就绪后仍残留 | 成功选择档案后仅清除该过期提示，不清除其他错误 |
| 看完周报再点全部记录仍停留在周报 | 全部记录显式打开统一历史；黑箱检查当前可见标签 |
| 深色分段被 Qt 样式刷新为浅色底 | 绘制读取明确的主题调色板；保留弹性运动、禁用和焦点 |
| 网页附件日期显示缺失 | 使用实际附件 date 字段，并显示为本地阅读时间 |

少数据页面保留真实空状态和下一步，不通过虚构指标、装饰卡片或无意义扩大控件填满屏幕。家庭页面只检查通用视觉一致性，未重排家庭业务。

## Skills、组件与视觉规则

实际使用项目内 [ui-polish](../../.agents/skills/ui-polish/SKILL.md)、[frontend-design](../../.agents/skills/frontend-design/SKILL.md)、[pyside6-fluent-ui](../../.agents/skills/pyside6-fluent-ui/SKILL.md)、[ui-ux-pro-max](../../.agents/skills/ui-ux-pro-max/SKILL.md)。先查询信息层级/导航密度，再检索组件；`tabs` 无匹配后改查 `segment`，读取实际 React Bits Rubber Segment registry/source/props。

保留已有 React Bits Rubber Segment 的 Qt 原生弹性分段与网页主导航连续选中运动，保留 Prompt Bar 输入反馈。来源、MIT许可及先前适配依据见 [组件来源](../ui-polish/COMPONENT_SOURCES.md) 和 [0.19.1视觉记录](UI_POLISH_2026-10-06.md)。本轮 registry 结果保存在本机 `components/`；未执行外部组件安装脚本，未给 Qt 引入 React/motion 依赖。网页三个入口使用已有按钮与显式 aria-pressed，不为装饰引入新组件。

视觉规则沿用暖白/草木绿/石墨、语义深色、系统中文字体。桌面侧栏172逻辑像素，主要区域上限1200，常规操作约44–48高度；结构以主操作、时间列表和报告正文为主，避免仪表盘式指标卡堆叠。高级动效服从 reduced-motion 和已有键盘/焦点行为。

## 最终结果

**本轮前端范围：已测主要流程与视觉审查 PASS；整体“所有功能可用、联网 API 对话”验收仍为 BLOCKED。** 缺少联网模型配置，且真实设备等上述内容未测，不能将此报告解读为全部功能通过。

最后两轮原生完整操作分别为 `final5-native` / `final5-native-dark` 和 `final6-native` / `final6-native-dark`。每次均完成五组主要流程，联网模型一项明确 BLOCKED。逐轮观察浅色1440和深色1024的九视图截图，并检查记录、健康和用药细节，没有再发现明显重叠、控件裁切、表格异常高度或主题不一致。

最后两轮网页为 `final4-web` 和 `final5-web`，均覆盖五种视口/主题，各上下文 `errors: []`。逐轮观察桌面与手机主要页面截图，补看深色首页、320宽度管家和记录页滚动后截图；长页末尾操作与底部导航之间保有可用空间。空数据的评估/健身入口保留简短说明和单一下一步，不用虚构内容填满画布。两轮之间没有继续修改页面布局。

最后补充的档案切换检查发现新首页周报摘要也需要随原有界面一起清空，已在原清空流程中补齐，并扩展现有切换测试；该项独立回归 **1 PASS（2.37秒）**。这是隔离呈现状态的修复，未改变正常页面构图。最终相关21项回归、该项定向回归，以及上述实际用户操作共同构成本轮回归证据。

# 健康模块 V1.3.1 正式集成验收报告

2026-10-13。本轮只集成移动 Web 健康模块，不推送 GitHub，不合并 main，不进入用药或家人改造。代码以本地 `feat/mobile-health-v131` 最终 HEAD 为准，完整哈希与备份结果见 `delivery.json` 和《本地代码备份与恢复说明.md》。

## 集成结果

健康首页按批准原型保留：搜索 + AI → 十项横向指标主卡 → 独立周报封面 → 健康工具 → 五栏纯文字导航。不增加“健康概览”、TEST 人物信息或固定演示数据标签。大卡、数值、单位、来源、日期、按钮、进度条、周报装饰分别为真实 DOM / CSS / SVG 元素，没有把截图放入正式页面。

十项顺序：活动步数、静息心率、血氧、睡眠时长、步行速度、体重、收缩压、舒张压、血糖、夜间醒来。源值来自现有 `/api/unified` 的 `snapshot.state.healthData.measurements`，按记录时间选最近有效记录。0 是真实有效值，null / 缺项 / 无效值不补零。保留原始数值精度，例如步行速度 0.92 和本轮 TEST 手填体重 62.25；展示手动来源与真实服务时间，不标成实时设备监测。

## 实际功能与接口

- `#health`：指标轮播和十格定位，当前指标只在本页会话中记忆，刷新后默认第一项。
- `#health/metrics`：全部十项、已记录 / 未记录筛选，返回健康栏目高亮。
- `#health/detail/{metric}`：真实最近14次离散记录图和全部原始记录，不插值新增点；保留服务 `snapshot.trends[metric].deltaText` 和真实 `baseline.mean/n`，缺基线不推断正常范围。个人基线明确区别于临床正常范围。
- `#health/record/{metric}`：`POST /api/product/health.record`，仅提交原 metric/value，原服务负责本人归属、单位、手动来源和时间。原数值必填 / 有限数 / 0–100000 校验、提交锁、失败草稿保持。收缩压与舒张压仍分别保存，不增加合并事务。
- `#health/weekly`：读取真实 `snapshot.history.report`。现有服务具备周报，因此没有采用原型“待完善”的演示占位，也没有开发新的统计 / 医学分析算法。页面沿用服务实际 `rangeText`，本次 TEST 为 2026-10-07 ~ 2026-10-13，不能把它误称为客户端重新计算的自然周。
- `#health/archives`：现有资料上传、下载、图片 OCR、回收站与确认恢复；原 `upload()` / `archiveDetail()` 控制器复用。原件默认本人私有，最多8MB，上传不自动生成指标。下载、trash/restore 都调用原接口，确认字段 `confirm:true` 保留。导出链接保留 `/api/product-backup`。
- `#health/profile`：本人档案和原编辑弹窗，保留旧 profile 合并保存；联系信息、设备、隐私与共享仍通过现有 `/capture?tab=more` 入口，不重写这些功能。
- `#health/rehab`：读取 `/api/product-rehab` 的真实综合记录数、训练数、最近项目、侧别、来源、时间和 next_step。综合记录包含其他运动，不能等同训练次数；实际 TEST 为24条综合记录和2次训练。进入历史或康复仍调用原页面。
- `#health/search`：只筛选已加载的十项指标与本人资料；明确不是全局健康搜索。
- `#health/ai/{metric}`：复用原 `assistant()` 和 `POST /api/product/chat`，采用与 V5.2 相同的安全预填方式：仅通用指标名称及问题，用户编辑后发送，不附数值、完整报告、身份或附件。保留原“本次不记录”、草稿和提交锁。返回保留指标、展开记录及点击入口时的阅读位置；实际复测回到105px且展开态保持。

重要代码依据：`mobile_rehab/static/health-v131.js` 为呈现与路由适配；原通信 / 档案 / 上传 / AI 控制器在 `unified.js`；原指标与权限约束在 `mobile_rehab/product.py`；周报和基线来自 `ankang/route1-health-agent/src/product/ProductService.ts`、`src/archive/healthHistory.ts` 和 `src/engine/baseline.ts`。以上后端 / 算法文件未修改。

## 真实浏览器验收

macOS 上使用 Codex 内嵌 Chromium 浏览器，未安装新浏览器、依赖或模型。截图来自真实页面、非 DOM 模拟。所有43张截图逐个校验为390×844或320×700，没有缩放补齐画面。`before-health-*` 两张复用阶段4.3实际审查的同一 f49fcdc 源码基线截图；批准 PNG 来自附件；其余截图均为本轮真实运行。

已观察通过：

1. 十项逐个定位，名称 / 数值 / 来源正确；鼠标大幅拖动从01只到02，大幅横向滚动从02只到03；进度条拖动可从03直达10；键盘 End / Home 可达10 / 01。
2. 主卡、全部指标、筛选、详情、趋势、记录、资料、档案、周报、搜索及康复摘要入口可用。首页与康复模块真实页面回归截图仍保留。
3. 未填写无法提交；0值草稿离开再进入可恢复；夜间醒来0和体重62.25通过原接口实际保存，刷新后仍可读，来源为手动、时间由服务生成；保存返回原指标，而非新增重复返回条目。
4. 上传新建的纯文本 `TEST V131 上传核验`，安全下载内容与输入字节完全一致；确认移入回收站，再确认恢复回资料列表。未读取真实资料，未操作永久删除。
5. AI 问题只含指标名，未自动发送、未附报告值；原隐私选项可用，返回指标与展开态和阅读位置保持。退出专注页后恢复原导航。
6. 最小 TEST 档案只有体重一条，其他指标显示“未记录”；空趋势不绘图，一条记录不伪造趋势。localhost 未配对会进入原连接流程，不显示健康内容。
7. 主动停止本轮18889 TEST服务，AI发送提示断连并保留草稿；记录保存失败保留63.45草稿、释放按钮；读取失败隐藏数值并提示重新连接。恢复同一服务后重连成功，未自动重发失败写入。

完整截图索引与原型并排对照见 `visual-review.html` / `截图索引.html`；文件尺寸和 SHA256 见 `evidence/verification.json`，关键操作结果见 `evidence/browser-checks.json`。

## 尚未解决 / 未验证

- 附件 `file:` 原型页面被浏览器安全策略阻止打开；本轮完整阅读HTML和说明，并核对批准的390/320截图，但不能声称已在浏览器运行该附件。交接包保留原型以便用户本地查看。

- 没有配置外部AI专业回复。当前入口是安全预填 / 原本地会话；未验证完整报告专业解释，不承诺AI读了完整病历。原会话本身仍可能读取已有获授权本人摘要，“本次不记录”不等于禁止读取已有摘要。
- 未操作真实摄像头、设备导入、HealthKit授权、OCR/语音模型或APK。未授权状态覆盖未配对和既有API权限回归，不声称穷尽所有授权撤销场景。

- 档案弹窗实际打开/取消已验证，提交规则由既有Python回归覆盖；本轮没有通过浏览器改写本人姓名或已有药物/家庭授权。健康资料图片OCR仅保留入口，专业效果未验证。

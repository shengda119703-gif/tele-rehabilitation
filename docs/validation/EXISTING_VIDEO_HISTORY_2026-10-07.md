# 已有录像进入普通历史 · 2026-10-07

## 操作范围

用户授权重新分析已有录像，并把实际结果保存到当前网页的普通历史。通过当前运行的统一 PhoneHost，先核对配对绑定档案，再分别上传一段康复评估录像和一段健身录像。沿用原 `mobile_rehab.analyzer`、`fitness_analyzer`、CameraManager 与本地 YOLO 姿态模型；未直接编写结果 JSON 或修改旧报告。

本轮没有改动前端布局、来源显示、分析规则或 APK。没有从相同评估录像构造额外训练完成记录，没有保存未经本人确认的安全筛查、疼痛或疲劳反馈。真实康复分析已提供自动训练建议；建议不等于已建立或执行训练计划。

## 实际验证

- 两个上传任务均由既有分析进程处理至 `done`，普通 `/api/jobs?brief=true` 历史列表和各自报告接口均可重新读取。
- 康复会话通过 `Storage(..., readonly=True)` 重开验证，档案归属、`REPLAY_FILE`、`SELF_USE`、已观察完整往返与逐次记录一致。
- 统一康复快照的录像来源能读到新评估，实时来源不包含该评估。
- 康复建议接口能根据新评估生成候选建议，没有自动代填筛查并建立正式计划。
- 原录像与服务保存的上传副本 SHA256 分别一致；录像回看接口与 `/capture?tab=history` 页面均返回 HTTP 200。
- 健身录像有较多必要点缺测，结果保留无法可靠连续计次的事实；未补点、改阈值或填入次数。
- 页面原有交互回归 `node --test mobile_rehab/tests/test_product_ui.cjs` 本轮 22 项通过，0 失败；不作为新增真人准确度或录屏验收。

## 查看入口

正在运行的统一网页：首页 → 我的记录与周报 → 查看手机分析报告。康复汇总记录需选择“手机录像评估与训练”来源。普通活动历史包含康复和健身筛选，可打开报告与原片回看。

接口与文件持久化已核对；本轮没有开展新的自动浏览器录屏或真人摄像头采集。个人原片、实际数值、完整身份标识、连接码及运行日志继续保留在本机忽略目录，不作为公开验收附件。未重新构建 APK，本机网页/桌面记录不会自动变成独立 APK 的本地历史。

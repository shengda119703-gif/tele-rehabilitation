# PR13 连续对话修复第一轮（2026-10-19）

仅目标分支 codex/unified-llm-entry-20261015。没有合并、部署、改动患者数据或放宽专业审核门禁。

## 修改

- 当前路由不再充当康复任务生命周期：健康咨询、动作质疑和普通闲聊不会删除未完成任务；取消、隐私、身份/来源变化、过期和安全流程仍按原边界失效。
- 健康/康复讨论追加任务原话并递增版本，将完整的保留任务原话传给回复层。纯“徒手”可以补充器材。此轮仍非完整结构化任务槽位管理器。
- 模型解析失败保留已有任务，并明确回复失败；新入口不再隐式调用旧单轮助手。未接通模型直接告知能力缺失。
- 本地编排回复使用 local/replied，桌面显示“本地编排回复”，不再将本地文案误报为未配置。实际无模型仍为 not_configured；恢复文案被规则拒绝为 invalid_reply。理解和工具执行结果另留 trace。
- 工具规划支持 region 进行公共训练卡检索；没有部位不从疾病名猜关节。此为结构化部位检索，不是向量语义检索或个人适用性判断。
- 无候选时进入任务恢复回复层；禁止恢复层推荐动作和剂量，增加保守表达检查。规则不能保证捕获所有无依据建议，仍需专项评估。
- trace 中空检索标 empty，而非 passed。

## 验证及限制

新增原场景四轮协议回归、解析失败/无模型、结构化检索和恢复建议拒绝测试。npm run ci：586 TypeScript 测试及36产品测试通过，构建和安全检查通过。桌面来源呈现测试：6通过（Qt offscreen，不是人工窗口验收）。

真实 DeepSeek 通过现有 chat-model.cjs 与 ProductService，以隔离内存 TEST 档案重放两次：任务版本均为1→2→3→4，原话持续保留；“练腿不行吗”能够引用前面的目标，未要求动作编号。未连接真实患者记录宿主，因此记录工具失败是该测试环境限制；未验证真实 Host/数据库计划写入。

首次真实重放暴露恢复模型绕过候选推荐动作，追加恢复防护；第二次两轮恢复被拒绝并诚实回退，第三轮保留上下文进行回答。因此对话自然恢复仍为 PARTIAL，不能宣称原场景整体通过。本地原始回执保存在忽略目录 .runtime/dialogue-live*.json，未上传密钥、配置或个人数据。最终细化了拒绝原因标记，不把它误报为网络错误。

当前仍缺：显式任务新建/继续/暂停/重开协议、完整结构化目标/限制/信息缺口、健康与计划混合意图编排、可靠自然恢复及更广泛语义检索、真实 Host 与模型完整端到端回归、专业审核至计划保存闭环。旧77项与UX表未重新评分；旧 PASS 不代表本轮实机验收。

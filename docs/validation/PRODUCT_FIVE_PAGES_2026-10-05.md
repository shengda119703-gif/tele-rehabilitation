建议按此顺序验收：

1. 首页右上“我的档案”：建立/切换本机身份，编辑本人资料。首次选择题可跳过；已有档案可从首页补充初始资料。
2. 首页“和康复管家聊聊”：进入原对话与点击式听写，识别文字先进入可编辑草稿，发送后才处理记录。
3. 康复：默认看当前计划和日期；“开始评估”进入原评估流程；“康复管家制定计划”在当前页读取已有评估。手动编辑直接在页面内完成。
4. 健康：上传或拍摄原图，查看资料、记录数值/身体情况、进入统一记录与报告。已配置识别服务时，核对并更正候选数值后确认保存。
5. 用药：添加已有医嘱药物，设置日期和时间，逐次标记已服用/跳过/未记录，查看更正历史。
6. 家庭：在家人的本机档案生成邀请码，切回本人确认关联；双方分别授权健康/用药/康复摘要，再查看只读近况。关系本身不开放资料。

## 2. 最重要的 UI/UX 改进

| 页面 | 现在回答的问题 | 操作与层级 |
|---|---|---|
| 首页 | 今天做什么？ | 主入口是管家对话，今日安排只列少量可点击条目；待办按需展开 |
| 康复 | 我的安排是什么，下一步怎么做？ | 当前计划、日期、开始评估；编辑时概览整体收起，返回后恢复 |
| 健康 | 我的资料和记录在哪里？ | 档案、身体记录、资料与图片、全部记录与报告；隐藏技术状态面板 |
| 用药 | 这一次药有没有服用？ | 按日/时间逐次记录，未记录不推断为漏服，更正留审计 |
| 家庭 | 家人允许我看什么，近期怎么样？ | 逐人分类授权、只读摘要、双方共享方向分开显示 |

黑白灰主题、克制反馈、浅深模式、焦点和键盘入口保留。没有为装饰增加动画或依赖。

## 5. 修复的问题

- 隐藏的旧页仍参与尺寸计算，造成概览额外滚动；活动页单独参与布局尺寸。
- 原计划摘要使用不匹配的设置键，次数/组数/休息可能显示不完整；改为读取正式键。
- 计划编辑和概览同屏堆叠；分为独立容器，快照刷新不会重新露出概览。
- 没有有效评估时仍显示“已安排基础练习”；空状态改为明确提示先完成有效评估。
- 拍照和识别前存档使用服务不接受的分类，导致保存失败；统一采用现有合法档案分类。
- 原图只从 CameraManager 已交付的新鲜实时画面保存；无画面、过期帧、错误来源不保存。
- 识别候选不能纠正数值；允许数值更正并通过原归一化/有效性校验，保留原候选与人工复核来源。
- 首次问卷“未知限制”不再被当成“没有限制”；本人表述进入原档案，不伪造测量结果。
- 首页安排链接在浅色主题中对比过低；按当前主题显式设置文字颜色。
- 服药更正历史显示机器时间戳；改为本地易读时间，持久化值不变。
- 家人近况详情暴露英文指标键和原始时间戳；改用中文名称、本地时间及中文关闭按钮，详情窗使用产品主题。
- 桥接构建原先先删除可用输出；改为编译后发布并保留上一份可用构建，Windows 同步目录重命名使用有界重试。

## 9. 尚未完成的产品能力与验收缺口

- **问卷完成后直接生成疾病康复动作计划未实现。** 现有自动计划需要有效动作评估；首次资料完成后先保存评估日期，明确没有动作处方。问卷不能替代测量。要改变这一点，需要用户授权新的医疗规则设计，属于本轮冻结边界。
- 当前自动计划是原有一般活动规则，不是自由生成的疾病/术后处方；本人限制等仍需原条件核对。
- 日期安排与原计划累计进度分开。已经完成的计划不会每天自动清零；界面明确需要新计划。没有擅自修改 Runtime 的轮次定义。
- 本机档案不等于邮箱/手机号/微信登录，家庭关系仅同一电脑不同档案联动；跨设备可信身份和远程共享尚未接入。
- 图片存档可用；实际 OCR 需要配置既有识别服务，未配置时明确不可识别。自动化验证使用测试候选，没有发送真实病历到外部服务。
- 新照片入口已经过画面/存档测试，但本轮没有进行真人病历实拍、真实 ASR、完整真人动作训练或手机通知实机验收。
- Python 环境位于本机 Temp 路径，目前可启动；后续环境维护应将已验证环境迁到稳定位置并重新验证，不要只修改快捷方式路径。

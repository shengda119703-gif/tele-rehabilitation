## API 与页面映射

|真实页面|数据/操作|必须保留的规则|
|---|---|---|
|`#medication`|GET `/api/unified` 的 profile.profile.medicationRecords 与 dailyProduct.medSchedules/doses|只列当前在用且日期有效的真实时段；未记录不转成漏服|
|`/meds`、`/detail/:id`、`/search`|同一本人快照；搜索为已保存名称筛选|停用药不丢失；无外部药品知识库|
|`/new`、`/edit/:id`|POST `/api/product/medication.save`|保留 id/name/dose/purpose/times/status；药名必填；原字符串长度与状态校验|
|`/times/:id`|POST `/api/unified/daily.medSchedule`|唯一HH:mm 1–12个，开始/结束，原在用药/归属校验；与药品文字服用说明分开|
|详情停用/恢复|POST `/api/product/medication.status`|确认，仅更改记录状态，不删除历史或宣称医生停药|
|`/log/:id/:date/:time`|POST `/api/unified/daily.dose`|用户主动选择 taken/skipped/unrecorded，当前归属与合法时段；未来日期不可写|
|`/history`|dailyProduct.doses / doseAudit|按计划日期读当前登记，按登记时刻读审计；原日期/时段与登记时刻不混用；最多300条审计|
|`/ai`|原 assistant() 会话；原发送、隐私选择、音频路径|可编辑预填，不自动发送，不新增模型后端或处方能力|
|旧 `/capture?tab=more`|原 health.js/product task.status|整体 medication_check 与逐次 daily.dose 不互相伪造状态|

## 数据与状态

选项由 medId/date/time 唯一键绑定；同药多时段、同时间不同药、未来只读、停用/改时已有历史更正均保留。原全局 busy 锁防止连续操作；草稿/滚动位置按当前本人和TEST/正式模式隔离，重新配对清除，未建立离线自动同步。

写入不确定时保留草稿并要求先读取核对；服务端确认但刷新失败也显示待核对。返回仍回原任务、原日期与原详情；编辑保存不额外叠一层详情。AI入口不增加药品/剂量/历史传送，沿用已有会话权限和“本次不记录”；不代表原会话所有现有上下文为空。

健康/康复/首页源码与素材、API适配/后端/DailyStore/TS域源码均字节不变；旧工作区可读测试和原回归通过。已保护边界证据见 freeze-and-scope.json、additional-rule-checks.json。

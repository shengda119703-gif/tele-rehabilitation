## 5. 未解决项与未验证范围

四项失败用例：

1. `test_extensions.py::test_real_local_model_live_empty_frame_no_false_counts`
2. `test_mobile.py::test_fitness_mode_real_model_empty_video`
3. `test_mobile.py::test_real_capture_model_and_empty_report`
4. `test_unified.py::test_real_blank_video_saves_under_desktop_owner_and_keeps_source`

共同直接原因是 `rehab_codex_single_camera_v2_1/app/vision.py` 的本地权重检查报“尚未配置本地 YOLO11n-pose 权重，程序不会自动下载”。这是当前环境阻塞，尚未观察到这些用例进入完整推理后的算法断言。**不能据此判定算法无缺陷，也没有证据把这四项归为本轮 UI 引入的代码缺陷。** 本轮只修正并复测了前端呈现／返回／反馈提交问题。

最小复测：经用户授权，优先定位已合法准备、版本相符的本地权重和现有模型依赖，记录路径及 SHA256；不自动下载。先在新的隔离 TEST 目录只跑上述四项，再用无个人信息的小测试录像走真实评估及已保存计划训练→结果→反馈→返回。确认计划、本人、侧别、来源、有效画面、计次及保存结果后才能补记端到端成功。若失败越过权重初始化才出现，则保留堆栈，另行判断代码缺陷，不改断言。

尚未验证：真人动作准确性、真实手机相机／权限拒绝、Android APK、桌面实时推理、RTSP 设备、完整实时指导、上传取消竞态和实际反馈保存失败分支、分享／撤销／设备切换／原录像永久删除、打印。没有为验证这些流程操作个人数据或开启外部服务。已有结果读取＋反馈保存通过不能代替新训练分析成功验收。

三张视觉封面需要专业核验；其余三张示例缺少真实 ID。专业动作介绍内容待提供。电脑历史在手机仅有原接口提供的摘要，完整报告留在电脑。这些限制均明确呈现，没有以演示交互充当已实现功能。

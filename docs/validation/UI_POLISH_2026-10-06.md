# 安康双端 UI Polish · 2026-10-06

本轮在 `31170f3` 统一主线之上进行表现层改造。正式桌面是 PySide6 Widgets，正式手机是电脑开启的共享网页；分别运行真实 ProductWindow/Runtime 和 SharedProduct/FastAPI，数据均为隔离 TEST，没有打开个人患者库。

## 设计与功能边界

视觉方向：暖白 `#f7f8f5`、石墨 `#25322b`、草木绿 `#345b44`、柔和分组面 `#e9efe7`；深色对应 `#18201b`、`#edf3ed`、`#b8d7bc`、`#2b392f`。中文沿用系统字体。桌面正文 15px、主标题 30px；手机正文 16px，主要操作至少 48px。色彩用于当前操作、选择和语义状态。只有需要组织操作的区域有表面，记录仍是时间行、原生表格或时间线。

| 范围 | 保留的行为与写入契约 | 表现层调整 |
|---|---|---|
| 首页 / 管家 | 原对话路由、草稿、私有轮次、语音确认、真实保存回执、Ctrl+Enter | 宽窗对话入口与今日时间表并列；窄窗自然堆叠；输入空白/可发送视觉反馈 |
| 康复 | 评估 / 下一项 / 完成 / 条件不足状态机，原计划、版本、日期、来源范围、保存和导航保护 | 下一项独立阅读面；管理工具与日期分离；动作库样式统一 |
| 健康 | 原附件、拍照、OCR候选确认、身体记录、原件、报告和回收站 | 档案与上传操作分组；保留原生 tabs 的弹性移动；窄窗操作为两列 |
| 用药 | `daily.medSchedule` / `daily.dose`，逐次记录、更正审计、未来日期禁用；未记录不解释为漏服 | 时间行和操作层级、触控目标、日期控件和主题一致 |
| 家庭 / 本人手机 | 本人连接码与家庭邀请码分离、逐人分类授权、默认不共享、家人只读、撤销与解绑确认 | 清晰的关系入口与共享说明；保留全部原控制与 action ID |

未修改 Runtime、API、业务服务、数据模型、医疗阈值或 Agent 推理。重排已有 Qt widgets 和网页元素，不新增产品状态。导航仍是原五个同级入口。保留原 Qt 弹窗/日历/select、标准网页表单、键盘和 Escape。

## 基于实际像素的修正

1. 原版桌面康复主操作、管理按钮和日期混在一条阅读线。改为下一项阅读面与独立管理/日期区，未改变按钮条件与处理器。
2. 第一轮宽窗首页的绿色对话面被 Qt layout 拉高，产生无意义空 hero。第二轮改用自然内容高度；1024 窄窗仍纵向排列。
3. 第一轮窄窗健康页上传工具纵向堆叠过长。重组为两列原按钮，宽窗与档案并列；全部信号、禁用条件和 ID 保留。
4. 手机 `/capture` 沿用旧版 `translateX(-50%)`，使新的浮动导航左侧两个入口移出屏幕。实际截图发现后清除旧变换，新增导航矩形完整位于 viewport 的检查。
5. 动作库 select 的旧 `max-width:45%` 相对其内部 label，导致内容裁切；给予真实可读宽度。320px 历史 chips 的负 margin 引起横向溢出，也已修复。
6. 原生身体部位菜单有独立紫色 QSS 与固定连接线颜色，改由当前语义 palette 供色，保留原插图、定位、按钮状态与信号。深色训练工作区不再回到白色大面。
7. 最后复查深色身体菜单发现 `background: white` 的空格未被早期替换处理，浅字落在白底；修正为匹配空白的样式替换，重新运行原生截图并打开确认。
8. 浏览器弹窗 opening 中间帧会混合背景，正式截图等待 settle；保留原生 dialog 焦点和 Escape，不把临时动效画面误判为静态透明面。

所有全量截图保留在忽略的 `qa-output/ui-polish-20261006/` 与应用 `qa-output/polish-detail-final/`，选定 TEST 截图在本报告同目录的 `ui-polish-20261006/`。脚本成功截图不等于视觉通过；本轮已打开并审查前后首页、康复、健康、用药、家庭、对话、原训练工作区、手机动作库、历史与弹窗图。

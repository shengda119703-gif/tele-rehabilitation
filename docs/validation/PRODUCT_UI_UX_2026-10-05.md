# 康复产品 UI/UX 自主优化验收 · 2026-10-05

本轮在 `codex/product-ui-v1` 的有效修复基础上继续，未 reset / checkout / merge main。正式前端是 PySide6 Windows 桌面应用；没有为接入 React 组件迁移技术栈。测试使用独立 TEST / SYNTHETIC 数据，不改写个人数据库。

## 1. 修改页面

首页、AI 康复管家、今日恢复、健康、用药、家庭、统一历史 / 报告与趋势、通知、设置。前四处有信息结构调整；其余页面应用统一控件、主题、空状态和时间显示。

## 2. 主要用户价值

- 患者首页先回答下一项训练与今日事项，窄窗四项摘要变两列，详细任务变单列。计划累计进度明确注明并非按日排期。
- 今日恢复把继续训练放在计划表前，流程、训练结果、评估和恢复趋势分组。摘要表按实际行数收紧，完整记录和原工作区仍可进入。
- Agent 根据真实 turn 展示理解与实际记录回执，区分本人 / 家人、发生 / 否定 / 假设 / 不确定、时间及澄清问题。详情弹窗可按 Esc 关闭；已有 Runtime 仍决定记录与确认流程。
- 对话区分主要回复、记录回执和可见范围；输入支持 Ctrl+Enter 发送、Enter 换行。回复到达不清空正在写的新草稿，快捷问题不抹掉未发送内容；无变化的刷新保留阅读位置和文字选择。
- 家庭页先看获准共享的关注提示、待处理事项和近期记录，再管理联系人。未绑定 / 未授权清楚解释摘要为何不可见，不把本机摘要称为对端送达。
- 报告保留既有解释与建议，仅展示有近期数据的指标，说明最近三天 / 个人基线和缺测限制。没有比较条件时不堆砌十行空指标。
- 黑白灰语义主题统一导航、图标、表格、输入、页签和按钮；功能性色彩保留。hover / pressed / focus / disabled 各有状态，不增加装饰性动画。

## 3. React Bits

研究了官方 [Stepper](https://raw.githubusercontent.com/DavidHDev/react-bits/main/src/content/Components/Stepper/Stepper.jsx) 和 [AnimatedList](https://raw.githubusercontent.com/DavidHDev/react-bits/main/src/content/Components/AnimatedList/AnimatedList.jsx) 源码及预览入口。最终直接引入 **0 个组件、0 个依赖**。Stepper 的显式阶段表达有参考价值；AnimatedList 的全局 Tab 处理与悬停改变选择不适合康复桌面键盘操作。实际实现采用 Qt 原生状态、详情展开及响应式布局，没有复制 React 源码或引入浏览器运行时。

## 4. 替换与保留

替换旧固定绿色产品样式、始终固定浅色的非核心页面、平铺回复、先管理后摘要的家庭布局和过大的空表空间。未删除核心功能、旧训练工作区、动作入口、图像确认、导出、撤回 / 更正、审计、通知或共享权限。已有 action ID、信号、数据所有者和后端命令保留；记录详情只是只读展示，不加入新的医疗推断或自动确认。

## 5. 发现与修复的缺陷

| 级别 | 问题 | 修复 / 复验 |
|---|---|---|
| P0 | 已保存训练反馈在嵌套网格中被标签高度裁切 | 原生标签按实际换行高度保留空间；长反馈宽窄窗测试及真实保存返回复验 |
| P0 | 回执新增后窄窗发送按钮超出可视区域 | 详情入口移到标题行，缩减卡片留白；1024×720 发送按钮可见 |
| P0 | 主题迁移时交替行继承黑色 AlternateBase，文字不可辨认 | 显式 QPalette.AlternateBase、选中背景 / 文本角色与 QSS；浅深色截图复验 |
| P0 | 异步回复清空用户后来输入的草稿，快捷提问清空未发草稿 | 按发送时草稿匹配清除；真实 bridge 回归 |
| P1 | 周期刷新重建对话导致滚动 / 文字选择丢失 | 内容未变化不重建；回归验证 |
| P1 | 家庭管理优先于近况，缺授权仍占巨大摘要 / 成员表 | 摘要置前，未授权和空成员收紧 |
| P1 | 趋势空指标堆积，已有基线的稳定数据仍称无基线 | 只列实际近期指标，保留真实比较与不足解释 |
| P1 | 非核心页主题、图标、焦点不一致；记录弹窗继承错误底色 | 统一语义 palette / icon / QSS，原生浅深及高对比复验 |
| P1 | 空表和个人资料的留白把下一步推远 | 空表收紧，设置和资料操作按上方阅读顺序布局 |

## 7. Build 与运行

Python 源码 AST 与 Git whitespace 检查通过，Node typecheck / build / bridge 通过。正式入口保持 `Start-Rehab.ps1` / `app.main`；没有新增部署或账号需求。

## 8. Regression

保留 Agent Runtime / understanding / grounding / persistence、人物 / 时间 / 否定 / 假设 / 不确定语义、确认、更正、审计、家属共享、药物和通知能力。没有修改这些核心实现，没有数据库迁移。本轮 41 场景无已观察到的业务 regression；Node 411+15 通过，UI 回归与语音模块复验通过。完整 Python 仍有缺权重失败和单次已恢复的启动超时，不能称全绿，也不能把测试之外的真人训练、远程模型或外部设备称为通过。

## 9. 当前边界

- 原训练工作区保持兼容的局部浅色主题；新的产品页面有浅 / 深 / 高对比路径。深色截图不代表旧工作区已经整体迁移，也没有新增用户主题设置入口。
- 家庭视图是获准读取的本机投影，没有新增跨设备家属产品或远程送达能力。
- 模型 / 语音 / 图像代理未配置时继续显示真实不可用状态。理解与记录详情仅展示最近一轮，长期事实和审计仍看已有记录页面。
- 原模型权重、真人动作素材 / 摄像头测量、ASR 与外部服务仍按原验收边界处理。
- 未加入医疗改善结论或新的临床趋势规则。

## 10. 建议下一轮

优先开展患者与照护者各一次真实任务可用性测试，验证首页任务、记录回执和授权摘要是否易理解；再补真人训练 / ASR / 外部设备验收与有权限的动作示范素材。其余阴影、动画和装饰调整收益较低，本轮停止继续美化。

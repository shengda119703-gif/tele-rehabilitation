## C. 康复页面最终逻辑

- **今日恢复**：先展示当前用户、来源、情境下的今日完成次数、下一项及计划累计状态。主操作是继续训练；无计划时解释先评估或安排计划。下方依次为恢复流程、最近训练结果与反馈、最近评估、恢复趋势和轻量管家入口。每周完成率以本周已保存训练为分母，中断和未核实目标不记成功。
- **训练流程**：复用原计划准备、输入、确认与开始。真正开始后进入专注模式；摄像头、动作、当前组 / 次数、指导、暂停、结束仍由原 Runtime 控制。保存失败仍提供重试 / 备份，不能绕过保存离开。结束后查看原报告、补记感受、保存并返回今日恢复；首页通过原 snapshot 刷新。
- **评估**：开始新评估、原身体档案及历史报告保留。摘要显示最近有效幅度、同动作同侧上次幅度和各自保存时间；无有效数据明确缺测。测量条件和可比性仍在原详情核对，数值变化不自动解释为临床改善。
- **计划**：人工计划库与自动计划继续调用原实现。累计项目显示已完成、当前下一项、已记录未完成或未开始；不把累计进度伪装成按日排期。SYNTHETIC / TEST 自动计划可检查接受 / 持久化，但不能用作真人训练。
- **进度**：历史训练、反馈、原历史比较和报告导出保持既有范围守卫。来源返回保留原筛选和记录位置。
- **AI**：问问康复管家打开同一个用户侧栏，不换一套模型，不伪造当前页面上下文注入。训练期间隐藏管家，训练后可继续使用。

53 个动作、图解、设置、步骤、摄像头 / 双摄 / 回放、身体档案、人工 / 自动计划、反馈、历史 / 报告、银发和家庭能力均保留。没有新增数据库 schema、模型能力或第二套业务实现。

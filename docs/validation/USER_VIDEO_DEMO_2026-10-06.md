# 私有用户录像：演示链路验收 · 2026-10-06

## 范围与隔离

验证对象是用户主动提供的肩外展 / 深蹲录像，以及用户授权后的录像兼容修复。先复现原文件读取失败，再使用临时兼容副本确认后续业务，最终重新用未转换原文件完成实际模型与 HTTP 接口链路。原文件不修改、不上传；截帧、逐帧关键点、完整个人报告、任务 / 身份标识和文件哈希只存在被忽略的 `.runtime/validation/2026-10-06/`，本文件不公开这些内容。

使用 FastAPI TestClient 驱动真实 `create_app`，不是 mock runner；Jobs 调用独立 Python 分析进程，复用 CameraManager / SourceWorker、现有 YOLO + 跟踪、康复控制器与规则计划。没有触发普通网页服务的停止 / 重启，也不接管现有浏览器或正式患者数据。API 测试数据根目录独立，训练复用评估文件，只用于验证训练链路，不是新增真人训练证据。简短适用性确认和感受是测试输入。

## 阻断复现与修复

1. 原录像能够解码，但 OpenCV 首帧 `CAP_PROP_POS_MSEC` 为负一个帧间隔；独立解码检查可见该媒体画面。原 SourceWorker 的时间检查将其拒绝，手机分析层将所有 ERROR 误写为无法解码。
2. 仅对起始、未 seek 的有限负时间前导画面提供省略路径，最多 4 帧且每个时间不小于 -0.25 秒；原视频实际各省略 1 帧。后续 PTS 原样使用，保存省略数量 / 原时间；不改变几何、置信度、计次、目标或身体评估门槛。中途负时间、重复、倒退、NaN、超界或超量前导仍拒绝。
3. 测试期间还复现了查询 `progress.json` 的 Windows 临时共享占用错误。原子 JSON 写入使用独立临时文件和最多 5 次短重试；读进度失败可略过可选展示，不能略过最终结果保存错误。最终结果长时锁定返回 503，前端有限重试，不无限等待，不覆盖已离开的页面。

## 用户演示下一步

手动运行“停止手机康复网页.cmd”再“启动手机康复网页.cmd”，手机刷新后，检查 `/api/health` 的版本为 `3.1.1`。肩外展可按正常评估 → 计划 → 训练演示。深蹲只需补拍 15–20 秒固定侧面，站立及下蹲时头脚全程入镜，避免前景床沿遮挡。手机实机点击、浏览器录像播放及相机操作仍需用户配合，不把 API 验收称为这些项目已通过。

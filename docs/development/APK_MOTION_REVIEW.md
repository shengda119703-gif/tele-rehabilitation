# APK 评估与训练：视频和上滑数据面板

2026-10-19，Android 0.5.12 / code62。

## 入口与操作

- 康复 → 活动度评估 → 选择动作 → 拍摄或选择录像 → 分析结果。
- 康复 → 我的计划 → 开始训练：原跟练相机、暂停、结束及目标保留；上滑可查看动作要点、镜头/语音设置，或选择“上传训练录像”。
- 训练录像结果 → 记录疼痛与疲劳 → 原反馈保存 → 原计划下一步。
- 历史记录打开已保存结果，也使用同一面板。已有关键点缓存的新录像可回看骨架；旧记录显示实际已有数据。

收起时只显示主要数值、结论和下一步按钮；上滑展开指标、曲线、重点回看、反馈与数据导出。当前值随录像原时间轴变化，全段值使用原报告统计。小屏收起时优先保留主指标和按钮，次要指标在展开后显示。界面不展示完成次数，计数和剂量仍保存在原业务层。

## 数据连接

1. `android_offline/web/motion.js` 仍调用原 MediaPipe CPU worker、`LocalEngine.measure/analyzeReplay`、原器械分析器；不替换角度、分期、计次或计划完成规则。
2. 同一次推理产生的可见身体点，以及通过原侧别/置信度条件的手点，按实际解码时间另存回看缓存。最多750帧，归一坐标，五位小数；不保存新视频、不填补遮挡点。
3. 缓存放在原 IndexedDB 文件库 `review:{job_id}`，带 `ownerId`、`jobId`；结果中只增加 `review_trace` 元数据。缓存失败不作测量失败，未提交的缓存会清理。
4. `GET /api/jobs/{id}/review` 仅在当前档案确实拥有该已完成任务、缓存归属一致、结构有效时返回；其他方法拒绝。不新增公网接口或共享权限。
5. `motion-review-data.js` 只读组装展示数据；`motion-review.js/.css` 移动原视频、按钮和表单节点，沿用原处理器，不另建保存/完成接口。

账号代数变化会销毁旧面板；异步缓存回复同时检查账号和页面。返回、切换页、AI往返及销毁会释放展示监听器；视频退出暂停，相机仍由原控制器释放。

## 指标来源

| 展示 | 来源 |
| --- | --- |
| 动作角度、全段活动范围、往返用时 | 原任务报告；全段峰值不拿稀疏回看序列峰值替代 |
| 双肩/骨盆连线倾角、躯干倾角、髋膝夹角 | 当前录像实际可见的二维关键点 |
| 左右屈膝角度差、膝部内外偏移 | 相关下肢项目的正面几何；不是两腿受力测量 |
| 骨盆移动、耳肩偏移 | 本片可见躯干尺度归一的百分比，不自动套身高换厘米 |
| 器械速度、加速度、水平偏移、功率 | 原器械报告中的有效数值及本次标定参数 |

只有实际存在的指标才加入面板；缺口保留空值，曲线不跨时间缺口连线。没有重量的记录不产生总功率；没有把之前六段样片的75kg、180cm、60kg或样片分析值写入患者记录。

回看缓存仅本机使用，不进入账号健康同步、家属分享或现有文字备份。跨设备仍同步原有评估/训练摘要和计划，不声称关键点录像缓存已跨端同步。正式托管实时测量/托管跟练保留原界面与规则，本轮新增样式覆盖APK本地评估、跟练和录像结果。

## 验证方法

`tools/motion-review/test_apk.cjs <私有输出目录> <本人授权录像路径>` 使用隔离浏览器和仅QA有效的身份，运行实际APK适配器及模型，不登录生产账号。`ANKANG_REVIEW_PACKAGED=1` 使用生成的APK资产；`ANKANG_REVIEW_REPLAY=1` 可复用该目录中先前真实跑出的QA评估，仍重新分析训练录像。输出和录像不放进APK或Git。

节点测试：`android_offline/tests/motion-review.test.cjs`；安装包一致性：`android_offline/tests/test_packaging.py`。实际结果见[本轮验收](../validation/APK_MOTION_REVIEW_2026-10-19.md)。

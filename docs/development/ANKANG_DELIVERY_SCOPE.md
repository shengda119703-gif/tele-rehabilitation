# 安康交付范围：电脑、安卓与苹果

2026-10-11：电脑版本0.23.0，独立安卓APK0.3.0。安卓包须重新安装，更新GitHub不会更新手机已安装的软件。

| 入口 | 管家与DeepSeek | 数据与连接 |
| --- | --- | --- |
| 电脑 | 普通多轮聊天、有限工具规划、本地模块查询与原有确认操作 | 电脑保存数据；Ctrl+Shift+D配置Key |
| 配对手机网页 | 使用电脑的管家与DeepSeek连接 | 连接电脑后台，使用电脑数据 |
| 独立安卓APK | 同一ProductService／Runtime核心，新增原生DeepSeek连接与手机康复只读宿主 | 手机保存数据；设置→智能服务→配置DeepSeek；也可长按头像进入原生菜单 |

安卓Key由AndroidKeyStore加密，保存在手机本机，不随备份导出。APK不内置私人Key。聊天发送当前普通输入与有限成功对话历史；健康档案和附件不会自动上传。未配置或请求失败显示本地回复；保存Key不等于联网请求成功，回复旁“DeepSeek回复”才是本轮来源。

当前具备12种模块只读查询、页面导航及原有服药记录／训练改期确认流程。任意模块写入、持续任务、通用多轮操作规划尚未实现。安卓这次实测普通聊天、上下文、隐私、本地模块与康复读取；不把这些测试扩大成全部工具规划和写操作验收。

## 苹果端怎样接回产品

“healthcare”是业务名称，不能仅凭名称认定使用了HealthKit。手动健康记录、数据模型、管家逻辑可以跨平台共用，设备取数需要平台适配。仓库有HealthKit适配器，但这次没有生成或验收iOS应用，也没有实现Android Health Connect。

如果原安康自动读取苹果健康／Apple Watch：保留苹果HealthKit入口，安卓另实现Health Connect入口，两者转成相同健康记录格式，再进入共同业务服务。取数权限、来源、时间和单位需要分别核对。DeepSeek连接不会自动完成这层取数。

独立安卓与电脑当前没有自动数据库同步；同一业务核心不代表同一数据库。本次不宣称已上架或已完成目标手机／临床验收。

验收证据见[安卓DeepSeek验收](../validation/ANDROID_DEEPSEEK_2026-10-11.md)。

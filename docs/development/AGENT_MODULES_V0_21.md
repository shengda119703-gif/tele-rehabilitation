# 0.22 管家对话、模块接入与自检指南

本轮把管家从单一康复查询入口扩展为多模块查询、页面导航和两类可确认的照护操作。你回来后可以先从电脑桌面的 **“安康康复（最新版本）”** 打开应用，选择自己的档案，再进入 **“康复管家”**。具体构建、验收结果和 Git 版本以本轮交付记录为准；本文说明功能和使用边界，不替代真人、临床或外部服务验收。

## 现在接通了什么

管家可以调用以下注册工具。是否可用取决于当前宿主实际接入的服务；“软件有这个模块”不等于“管家获得该模块的全部权限”。

| 工具 | 当前返回的真实内容 | 边界 |
| --- | --- | --- |
| `health_overview` | 当前本人已有健康测量和发现概况 | 不是诊断；完整数值、时间和来源在健康页核对 |
| `medication_list` | 已保存药物、用量文本、时间文本和使用状态 | 不新增处方，不调整用量 |
| `archive_list` | 本人资料、图片、视频附件的元数据 | 不读取附件正文，不自动把上传资料带入对话 |
| `family_status` | 家庭绑定与持续共享授权状态 | 不绑定家属，不授予权限，不发送消息 |
| `notification_list` | 已有通知台账和通道状态 | 台账或受理状态不等于外部送达 |
| `extension_status` | 语音、设备适配器、HealthKit、同步和通知通道的连接状态 | 已配置不等于目标设备或服务实测通过 |
| `daily_overview` | 今天已保存的服药状态和训练安排 | 未记录不等于漏服；安排存在不等于训练完成 |
| `rehab_next` | 已保存计划下一项及原业务门禁结果 | 不替你开始训练，不绕过原康复规则 |
| `rehab_plan` | 原康复模块保存的计划事实 | 宿主提供康复只读接口时可用 |
| `rehab_assessments` | 原康复模块最近评估事实 | 不重新评估，不推断疗效 |
| `rehab_history` | 原康复模块训练历史和反馈事实 | 不将“已安排”写成“已完成” |
| `agent_capabilities` | 管家当前开放的工具和限制 | 以实际可用工具为准 |
| `open_module` | 打开首页、康复、健身、健康、用药、家庭、管家、记录、设置或通知页 | 健身进入既有健身模式；体态、居家工具说明原工作台入口。导航不启动相机、训练、分享或删除 |

本轮新增的调度写入只有两类：记录已有服药安排的状态，以及修改已有训练安排的日期、时间。它们经过 `CareCoordinator` 生成待核对操作，调用原服务保存，并核对真实回执。原健康对话中的身体情况记录、更正、隐私与安全路径仍按原有规则处理。

## 回来后可以这样检验

先使用自己的演示或测试档案检验，再决定是否记录真实事实。下面涉及药物和训练的例子需要先在原页面保存对应资料与安排。

| 输入或操作 | 应看到什么 |
| --- | --- |
| “查看健康记录和药物清单” | 分别读取两个模块的已有事实；无记录时明确说明，不编造内容 |
| “打开用药页” | 跳转到用药页；不修改药物和服药状态 |
| “记录今天08:00的某已保存药已服用” | 把“某已保存药”替换成档案中的完整药名，并确保今天08:00在其已有安排中；先出现待核对操作，不立即写入 |
| “今天14:00的训练改到16:00” | 今天14:00有唯一、有效的已有训练安排时，显示原时间与目标时间；只改安排，不改计划内容、剂量或完成状态 |
| “查看资料”“查看家庭状态”“查看通知记录”“查看设备状态” | 返回对应模块现存资料或连接状态；没有配置或没有记录时明确说明 |
| “今天有什么安排”“康复下一步是什么” | 返回已有安排或原计划下一项；不会自动开始执行训练 |

“已服用”应来自实际发生的事实。管家不应为了检验功能而把未服用的药写成已服用。找不到药物、没有对应时间、存在多个训练安排，或描述超出支持格式时，应先核对资料或澄清需求。

## 核对、取消与执行结果

在管家页的 **“核对操作”** 入口查看待处理任务。配对网页在管家页显示 **“待核对操作”**，点击 **“核对操作与结果”** 查看详情。核对每一步的对象、日期、时间及目标状态，再确认执行。

| 状态 | 应有的行为 |
| --- | --- |
| 待确认 | 首次确认前没有业务写入；可以取消 |
| 已取消 | 显示未执行，不把取消写成保存成功 |
| 确认过期 | 首次确认有效期为15分钟；过期后重新提出需求并核对当前事实 |
| 已保存 | 只有原服务返回完整、匹配的保存回执，才显示该步已保存 |
| 部分已保存 | 分别展示已保存、失败和未执行步骤；不能把整项任务说成完成 |
| 失败或执行待恢复 | 核对实际记录后重试未完成步骤；成功步骤通过持久回执避免重复写入 |
| 已开始执行 | 取消不能撤销已经发生的事实；必要更正仍在原页面进行 |

关闭并重新打开软件后，同一本人、同一数据来源和使用情境的待确认或待恢复操作可以重新读取。恢复不等于自动继续执行；仍需查看结果并明确确认或重试。页面切换了本人或来源时，旧确认操作不能沿用到新档案。执行前原记录或计划已经变化时，应拒绝沿用旧提案并要求重新核对。

有多项待办时，完成一项后保留该项实际回执，下一项需要重新选择再确认。公开状态、家庭视图及导出备份不包含确认凭据；备份中的照护内容是审计记录，不能用备份直接恢复可执行凭据。

如果页面提示无法读取待确认操作，先刷新并核对；不要把读取失败当成“没有待处理任务”。已过期任务不再作为可确认操作展示。

## 人物、时间和异常用量

照护写入绑定宿主提供的本人、来源和使用情境，不由模型或对话自由指定。第三人的训练或服药描述不能默认写到当前本人档案。例如“张三今天14:00的训练改到16:00”“我朋友今天14:00的训练改到16:00”应要求核对人物，不生成本人的执行操作。

查询与导航也先核对输入意图。“不要查看健康记录”“假设查看资料”“王五今天的安排有哪些”不会调用本人查询工具或联网规划；未识别的主体需要重新明确。否定、假设、引用和更正指令保留原处理路径。

时段与时钟必须一致。“改到上午16:00”“改到中午四点”等矛盾或不明确时间，应要求澄清，不能自行改成16:00或04:00。未支持的分钟描述也不能截断成整点。

“已服用两倍剂量”“多吃了”等描述不能被降成普通“已服用”记录，也不能沿用原用量掩盖异常。应保留原话的含义、核对实际用量，并走原健康与安全处理路径；本轮照护执行工具不会调整处方，也没有新增异常用量的独立结构化医疗记录流程。对话是否保存仍遵循原隐私设置。

## 本地查询与 DeepSeek

常用查询、页面导航和有限格式的照护需求有本地确定性处理路径。没有可用模型时，仍可使用上面的明确示例；不应把“模型未配置”显示成整个管家不可用。

DeepSeek 是可选的联网理解适配器：模型只能从当前开放的工具中给出受限计划。执行前会核对整个计划的工具名、参数、可用性、重复操作及数量上限；未开放的工具或额外字段不能执行。工具返回的事实由本地适配器组织回复，模型不能凭空生成保存或送达回执。

0.22.0已新增普通聊天路径。打开桌面最新版→康复管家，输入“你喜欢我吗”或“今天想和你聊聊天”，有本机有效Key时会真实调用DeepSeek，回复旁标明“DeepSeek 回复”。再问普通追问，最近成功的普通对话可作为上下文。健康事实、隐私、紧急处理及真实操作保持原服务路径，不从模型文本新增健康记录。没有Key或请求失败时，标签明确说明本地回复。只保存Key不代表每条输入都走模型。

配置入口仍为软件窗口中的**Ctrl+Shift+D**，输入DeepSeek API Key并保存；密钥保存在仓库外的本机私有配置。0.21.1已修复Windows保存Key后重启后台的WinError 50。本机0.22.0用隔离TEST空资料实测四次DeepSeek请求：两句截图原话及两轮代号上下文全部通过；不代表所有开放模型工具、设备或长期网络可靠性均已验收。私有密钥不写入仓库或报告。

## 电脑、配对网页与独立手机端

| 入口 | 本轮能力所在位置 | 检验时要分清 |
| --- | --- | --- |
| 当前电脑桌面产品 | 当前仓库的 Python 宿主、Node 桥与 TypeScript 产品服务 | 本人及来源由宿主隔离，调用本机已有模块服务 |
| 与电脑配对的网页 | 当前统一网页资源及对应电脑后端 | 可使用管家查询、导航和待核对操作；需连接当前电脑服务 |
| 已有独立 APK 0.2.1 | APK 内打包的旧资源和本地适配器 | 更新电脑仓库不会自动更新已安装 APK；不能据此认定新管家功能已进入旧 APK |
| iOS／HealthKit 桥接 | 可选宿主适配器和连接状态接口 | 查询配置状态不等于 iOS 产品发布、真机授权或 HealthKit 数据流验收 |

不同端的数据库、附件和历史不能因为页面相似就认定已经完全同步。本轮没有重新发布独立手机安装包。

## 扩展架构和下一步边界

当前扩展链路是：**确定性工具注册 → 本地命令或模型受限计划 → 整体计划校验 → 真实模块服务执行 → 按实际事实与回执回复**。读取和导航由 `ProductAgent` 管理；照护写入由 `CareCoordinator` 的确认、来源核对、预期事实和幂等回执管理；产品服务负责连接已有模块。安全、隐私、更正与原健康处理路径保持优先级。

后续接入新的写操作，需要为该模块定义清晰的输入、权限、确认、前置事实、保存回执和失败恢复规则。不能仅把所有产品接口名称提供给模型，就声称完成全模块调度。

当前仍没有全模块任意写入、持续后台任务、通用多轮规划、相机或训练自动操作，以及已经送达的外部通知。分享授权、处方编辑、附件导入与正文处理、导出／清理、设备连接、相机和训练开始等必要操作仍由原页面承载。本轮提供模块查询、导航和有限确认执行的基础，不能将其描述为所有模块已经完全自动化。

### 20.3 P1：记录、恢复与三端接线

#### R01 权威模式分段与分来源保存汇总

**当前边界：**正式网页能将视觉会话关联到同一跟练旅程，练习和视觉分别确认保存。observationSegments 只是客户端展示变化，服务器 mode_segments 尚未完整接通，不能把页面起止时间算成有效运动／有效保持时间。

**剩余工作：**

- 先核对现有 writer 和模式事件能力；确有缺口才提出最小版本化契约，不根据示意字段猜 API。
- 每段明确本人、执行器／来源、原旅程、视觉会话、组次、原 epoch／revision，以及暂停、缺测、恢复、结束原因。事件重复、迟到和中断重开必须有确定处理规则。
- 原来已经确认的视觉事实保留；跨缺口不补确认次数，不把重新校准前后片段直接拼成连续有效保持。
- 统一显示练习记录、视觉事实、感受、报告各自状态。某一部分 COMMITTED 不替其他部分确认保存，报告失败也不撤销已保存事实。
- 自动次数、自报总数、确有来源的估计、页面练习时间分别保留；不能相加成新的自动次数或正式计划贡献。

**验收：**实际覆盖等待→陪练→恢复观察→暂停→继续→结束；原键重放不新增段或贡献；刷新后读回同一份记录。接口缺失时保持真实“未接通”边界，不用客户端时间段冒充服务端事实。

#### R02 Qt／APK 本地旁路与三端能力矩阵

**当前边界：**三端已有独立跟练并非没做。新正式相机旁路只在明确启用 v2 的网页入口接通；PHONE_LOCAL 不声明托管正式测量能力，Qt 也不能靠换 API 地址自动获得该能力。

**剩余工作：**

- 列出每端“说明／已有安排／可选观察／正式测量／独立保存／感受／历史／恢复”的实际入口、执行器、库和能力开关。
- Qt 通过原 Runtime／SceneController／Storage 接线；APK 通过原本地执行器、桥接和 Store 接线。保留当前窗口、控件、页面、图标和样式。
- 补当前端实际支持的可选观察与关联，并串起准备、缺测降级、暂停、结束和分部分保存；没有相应正式能力时保留已有允许的本地跟练路径。
- 始终保留各端真实来源；不得把 PHONE_LOCAL 写成托管 LIVE_CAMERA，也不得直接借用另一执行器的 plan、session、operation 或患者标识。
- 后端未启用、能力未知与执行资格拒绝分开处理。技术失败不改变模型、剂量、专业规则，不通过默认全勾确认绕过条件。

**验收：**分别从桌面原入口、托管网页和实际 APK 完成至少一条允许的开始→练习→结束→历史路径；当前端不支持的能力不会循环请求，也不显示假成功。

#### R03 桌面 Qt 训练感受后补

**剩余工作：**

- 在原结束区及原历史详情接独立后补／修改入口，不要求重新训练。
- 只保存用户明确输入的疼痛、疲劳和不适说明；未填写保持 null，不能补成无痛或 0。
- 沿用原反馈身份与版本规则；原练习保存和感受保存分别确认。
- 处理丢回复、断网／进程重开、旧反馈迟到和真实版本冲突；保留本次填写，冲突时明确选择，不自动覆盖。
- 不让新反馈抹掉原停练事实；下一项是否允许继续仍按原规则核对。

**验收：**已保存练习可以稍后补感受；回复丢失后找回原结果；两窗口修改不会静默丢内容；感受失败不要求重拍或重练。

#### R04 跨进程待办恢复与保存操作队列

**当前边界：**现有按作用域草稿、原键查询和网页刷新恢复是基础，不等于 Qt 跨进程或全模块 outbox 已完成。

**剩余工作：**

- 为必要的创建、结束、继续下一组、感受及上传核对保存不可变操作键／载荷和状态；复用原存储，不建第二个患者事实库。
- 区分待提交、结果未知、待核对、已确认、冲突及不可恢复；不能将“请求发出”当作保存成功。
- 同键只重发同载荷，先查原结果；结束意图优先于尚未发送的恢复／继续意图，已提交操作不因旧 GET 回退。
- 进程重新打开后找回原身份和未完成意图；不自动开相机、补次数或重播旧语音。
- 本人、服务器、origin、执行器或档案变化后暂停不匹配操作，不能把旧人的内容自动发给新本人。
- 重试和队列必须有界；损坏数据保留可导出内容，不以清空草稿或无限重试掩盖故障。

**验收：**在请求前、服务器已提交但回复未到、客户端确认前等边界中断，再次打开均不重复创建／贡献；无法核对时保留输入和导出入口。

#### R07 同旅程跨窗口主动控制与接管

**剩余工作：**

- 使用各端真实支持的跨窗口／跨进程协调机制，为同一旅程建立主动控制权；仅内存布尔值和幂等 finish 不足以完成本项。
- 另一窗口默认只读或明确请求接管，不能同时发帧、申请相机、计时或发送控制。
- 接管、窗口关闭、异常退出、租约过期、恢复旧窗口及切本人都要验证；迟到旧响应不得重新取得控制权。
- 刷新后先核对控制归属再执行；显示可理解的状态，不要求用户处理锁和 revision 等术语。

**验收：**同时打开同旅程的两个窗口，始终只有一个有效主动采集者；接管后旧窗口不能继续采集／续练；相机和音频无残留。

### 20.4 P2：公共体验、录像、语音与故障场景

#### R05 全模块独立加载、局部重试与错误收敛

**剩余工作：**

- 核对统一首页仍等待全量 snapshot 的入口，拆分或采用实际已有的独立请求能力；历史、报告慢或失败不锁住已有可用训练与导航。
- 首页、档案、计划、历史、报告，以及用药／健康／照护／家庭等既有模块只补公共加载和错误隔离，不重写其业务。
- 按本人、来源、版本管理缓存和在途请求；保留当前输入，迟到旧响应不抢新页面。
- 只对需要的数据局部重试；技术错误、必填信息、权限和真实执行阻止分别显示。不要解析一段模糊报错来猜医疗资格。
- 非当前动作所需的头像、身高等资料不拦已有允许的练习；必要条件仍在真正使用时核对。

**验收：**人为延迟／拒绝历史和报告，首页及训练入口仍可用；切页和切本人没有旧数据回写；局部重试不重建相机或清空已填内容。

#### R06 原录像持久恢复、原作业查询与报告重建

**当前边界：**原上传操作键及查询原 job 已接，同页面原文件可复用；跨刷新／进程重开可达的媒体引用、派生报告重建仍未完成。断点续传只在实际接口支持且确有需要时实现，不预先声称已有。

**剩余工作：**

- 保留上传操作、原 job／session 和文件身份；本地引用按各端媒体存储能力实现，不只存一个重开后不可用的内存 File 或 Blob URL。
- 原文件引用失效时允许重新选择原件并核对绑定；原片仍在时不要求重新拍摄，不能把不匹配文件静默绑定到旧 job。
- 上传回复丢失先查询原操作；404 不能直接证明原上传已经退出，不能盲目另建同一评估。
- 原 session 已保存而报告失败时只查原事实或重建派生报告，不重跑成第二份评估、不重复贡献。
- 分别显示接收视频、分析、事实保存和报告的状态；能力缺口对应 B05，不用“已上传”概括全部成功。
- 存储失败保留可用身份和输入；原视频不能塞入小型 JSON 草稿、公开文档或 Git。

**验收：**跨刷新／进程重开、弱网回复丢失、原片重选、报告失败分别跑通；服务已有原片时不重新录制，实际作业与事实数量不重复。

#### R08 全产品语音与提示单出口

**剩余工作：**

- 将 Qt、其他网页／模块及仍独立的浏览器适配器逐一纳入当前端的统一输出规则；不是让三个执行器共用一个患者状态。
- 只接受当前本人、来源、会话、相位、证据和有效期的提示。缺证据时减少纠错，不编造完成或下一阶段。
- 保留当前单候选、去重、间隔和取消规则；暂停、结束、离页、换本人、后台及接管时立即停止旧输出。
- 在实际设备核对中文 TTS 是否可用、音量／静音行为、延迟初始化和迟到 onend；没有声音不能仅因调用成功就算验收。
- 不新增敏感权限、联网语音服务或自动下载语音包；保持现有语音入口与视觉样式。

**验收：**快速暂停／继续／换阶段、切后台及旧回调迟到不会连播或播过时口令；真机能听到当前有效提示，结束后不继续说话。

#### R09 三重点动作与缺测／旁人输入

**剩余工作：**

- 肩外展补真实主指标与辅助质量分离、转折遮挡、反复长短缺测、旁人入镜和恢复的完整输入证据。
- 坐站补初始站姿、起身、坐回、扶手／椅子安排及原地晃动；晃动不能制造多次自动确认。
- 康复深蹲补当前协议、正／侧位必要点不足与返回起点；不能把髋角冒充膝角，也不引入竞技深度要求。
- 在适用端验证相同旅程不中断、已有记录保留、普通缺测不弹窗／清零／重拍；真正停止或身份不清时按原规则处理。
- 冻结实际输入与人工逐段参考，分别报告开始、陪练、自动观察、结束、保存的尝试数；兼容通过与识别准确性分开。

**验收：**三个动作各完成允许的用户旅程与负场景；未观察到的转折不补成完整次数，旁人动作不归入当前人。无合格评估时不通过 TEST 夹具冒充人体正式安排。

#### R10 双存储满、草稿损坏与来源切换

**剩余工作：**

- 实际覆盖客户端写失败但服务可保存，以及客户端与服务端同时容量不足；保持真实保存状态和恢复／导出入口。
- 处理草稿损坏、配额／缓存被清理、原文件不可达、格式不支持及服务忙；不统一归为“请重拍”。
- 验证退出、切本人、切服务器及重新进入时，旧草稿／队列／回复不会串人、串执行器或覆盖当前输入。
- 为授权、技术、观察不足、缺必要输入、执行阻止等原因补全当前入口的结构化映射，未知原因不猜允许执行。
- 故障注入使用隔离库和限定配额，不为测试填满用户真实系统盘、删除患者记录或损坏在用数据库。

**验收：**双存储失败时不显示已保存、不无限重试；已有事实仍可读，未保存输入可恢复／导出；新本人不会收到旧人的自动补交。

### 20.5 P3：目标设备、完整验收与交付

#### R11 红米 K60 Ultra 与真实生命周期／性能

**未实测内容：**

- 权限弹窗忽略／拒绝／迟到、前后相机、横竖屏、系统返回、切应用、熄屏、进程回收后重开，以及低电量／低性能。

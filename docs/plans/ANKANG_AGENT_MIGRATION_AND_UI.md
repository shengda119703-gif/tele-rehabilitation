# 安康 Agent → 居家康复助手：完整迁移与 UI 方案

更新：2026-09-29。持续开发分支：`codex/rehab-agent-stage1`。0.23.0 已落地 A 的有限结构化自述、逐条确认保存、定向撤回与重开闭环；等待用户人工验收后才进入 B。隐私意图仍分开处理，分享请求只引导到现有家庭设置。见 [A 阶段 UI / 数据合同](AGENT_STAGE_A_UI_AND_DATA.md)。

## 一句话目标

把安康的“理解老人说的话 → 核对真实资料 → 决定可做的事 → 取得同意 → 执行并留回执”移到康复项目，而不是仅复制聊天框。原康复评估、训练、摄像头和数据库继续拥有事实与执行权；大模型负责理解与解释，不代替康复规则或医护人员。

## 当前实际位置

康复项目 0.23.0 在 DeepSeek 聊天、多轮追问、只读评估/计划/历史查询、本机纵向比较和安全导航上，增加了有限结构化自述的确认保存及定向撤回。它仍是安康 Agent 的**部分能力迁移**，不是“安康 Agent 全部移植”。当前界面是 820×700 的“康复管家”弹窗；“银发健康守护”另有独立弹窗，两者尚未形成一个用户流程。

| 安康原项目能力 | 康复项目现状 | 迁移方式与边界 |
| --- | --- | --- |
| 自然对话、模型适配和回复边界 | **部分完成**：DeepSeek、格式检查、回退 | 保留现有 Python 实现；增加明确的回合规划，不复制 React hook |
| 逐句理解：本人/家人、现在/过去、发生/否定/假设/不确定 | **A 最小闭环已实现**：本机有限语法分离人物、时间、肯否及确定性，未知不入库 | 改造成结构化“陈述”；不确定时追问，不把“昨天妈妈头晕”写成本人今天不适 |
| 更正和撤回之前说错的事实 | **A 最小闭环已实现**：按来源消息 / 具体自报逐条确认撤回，保留审计 | 每条可保存陈述关联来源消息；只撤回对应陈述，不改动摄像头原始评估 |
| 个人状态 / Person Twin | **可用资料不同**：已有康复记录和银发变化卡，但无安康所需的步数、睡眠等完整序列 | 建“康复状态摘要”：可比较的动作、未完成任务、本人感受与缺测。缺数据写“未知”，不可照搬安康阈值 |
| 发现变化 → 待办 → 确认/完成 | **部分重叠**：训练计划、银发 request/feedback 已有 | Agent 通过受限工具调用原有服务；先建议与预填，写入/开启/分享需本人确认；避免第二套任务库 |
| 私密/不记录/一次性告知家属 | **部分完成**：本轮已拆分意图与隐私回执；银发模块有分类授权 | 继续统一“本轮是否联网、是否入记录、是否共享”三个独立决定；真正分享要确认、回执与审计 |
| 家属查看、通知、认领、回应 | **仅本机演示**：银发角色和测试手机网页 | 先接已有本机授权与请求状态；真实远程通知必须另有身份认证、传输、送达状态，不能把“本机已保存”说成“家属已收到” |
| 语音输入/播报 | **银发模块有独立测试入口；Agent 对话未接** | 将语音视为聊天输入/主回复的界面适配器；文字始终可用，录音/权限可见 |
| Home Twin / 找药、找物 | **康复项目没有真实物品位置库** | 保留独立 `home.find_item` 工具契约；只有接到用户确认的房间/物品位置数据后才显示位置。高斯泼溅画面是可选呈现，不是 Agent 推理事实来源；默认不生成“百度地图路线” |
| App 端 UI | **技术不同**：安康 React Web，康复 PySide6 桌面 | 迁移交互与状态，不复制 TSX/CSS；复用当前康复页面与银发服务 |

## 目标架构（先接得稳，再扩范围）

```text
输入（文字；以后可选语音）
  → 隐私门禁 + 结构化理解
  → 回合规划器（纯逻辑、可测试）
     ├─ 普通陪伴回复
     ├─ 康复只读查询 → 已有评估/计划/历史规则
     ├─ 待确认操作 → 已有训练/银发服务
     └─ 找物查询 → 独立 Home Twin 工具（没有真实位置就回答未知）
  → 执行器（检查身份/范围/授权/版本，留下回执）
  → UI：主回答 + 事实依据 + 操作确认 + 隐私/送达状态
```

最重要的接口不是一个“万能 prompt”，而是一份受限的回合结果：`reply`、`understanding`、`evidence`、`proposed_actions`、`privacy`、`receipt`。`proposed_actions` 只能是白名单动作，不能把模型生成的文字当作已执行命令。安全阻断、训练剂量、评估有效性和家属授权仍由本机既有规则判定。

## 分阶段实施及可人工验收结果

### A. Agent 核心与对话记录（A2 开放词汇抽取，待人工验收）

1. 把安康 `understanding.ts`、`elderTurn.ts` 的**数据结构与状态流**适配为 Python；A2 使用受限 DeepSeek 开放词汇抽取 + 本机 validator，删除正式自报症状词表。未配置或失败明确不可用，不伪装回退。
2. 区分“仅聊天历史”“本人自报事实”“摄像头评估事实”，并记录来源、时间、用户范围与确定性。只有本人明确陈述、语义确定且同意保存的事实才入自报记录；否定、假设、家人情况不入本人记录。
3. 支持“我刚才说错了”的定向更正；回合结果分成主回复、记录回执、隐私回执。
4. 人工验收：连续说“昨天妈妈头晕”“我今天没头晕”“我刚才说错了”，界面不生成错误的本人当前不适；清空/关闭后对话记忆规则可预期。

### B. 康复工具与任务闭环

1. 将现有只读 Agent 查询注册为显式工具；模型只能提议，工具重新按用户/来源/情境核对。
2. 接已有自动计划、训练任务、银发 request/feedback，不创建平行的“Agent 计划”。问“今天要做什么”给出真实下一步和原因；问“今天不练了”先回应，再提供“暂缓/返回训练页”等明确选择。
3. 一切会改变计划、标记完成、记录感受或发起请求的操作，先给确认卡；执行后给“已保存到本机/未完成/等待家属回应”的真实状态。
4. 人工验收：有计划、无计划、过期评估、不适、用户取消确认、保存失败都可演示；没有一次靠模型文本越过原流程。

### C. 个人状态与家庭协同

1. 以康复项目真实数据制作“康复状态摘要”，显示“已观察/本人自报/未取得”及可比条件；不移植安康步数/睡眠/心率阈值到不存在的数据。
2. 合并 Agent 的家属操作与现有银发授权页。先实现同电脑的授权、一次性分享、请求、家属回应、撤回和共享审计；之后若要真实手机使用，再单独建设账号、身份验证、远程服务和送达确认。
3. 人工验收：未授权不能看；撤回后新读取不可见；“已在本机创建请求”与“家属已收到”永不混淆。

### D. 语音与家庭空间工具

1. 将现有语音能力接到 Agent 的输入与**主回复**，提供文字回显、停止播报和失败时键盘回退。
2. 定义 `home.find_item` 输出：物品名、经用户确认的位置、更新时间、可信来源、可选房间标注；没有物品数据就说“不知道”。
3. 待房间建模/物品标注真实接入后，UI 在房间图上高亮药的位置；路径导航不作为第一版要求。健康/用药问题不转成找物查询。
4. 人工验收：找药只能显示存在于真实位置库且足够新的标注；绝不凭大模型想象位置或路线。

## UI：保留桌面端，收成一个入口

建议把右上角“康复管家”从弹窗升级为主窗口中的“助手”页（或宽侧栏），银发模块的家庭功能作为助手页内入口，旧评估/训练/档案/历史仍保持原页面与原逻辑。先实现清楚、可用的结构，不急着重画整套康复 UI。

```text
助手
├─ 今天：真实下一项训练、待确认的事、最近一次结果
├─ 对话：主回答；下方折叠“依据/记录回执/隐私状态”
├─ 事项：我提出的请求、训练任务、家属回应及状态
├─ 家庭：授权范围、一次性分享、共享历史（远程未连接则显著标明）
└─ 设置：DeepSeek、语音、数据与隐私
```

对话里的操作用按钮卡片区分：**查看**（只读导航）、**确认后执行**（可能写入/共享）、**不可用**（缺真实位置或远程服务）。家属回应不能和模型回复画成同一种气泡。不要把大模型的“我已经通知”当作送达回执。

前端可依赖的最小数据合同：每条回答有 `main_text`、`source_label`（模型/本机/本人自报）、`evidence_summary`、`receipt`、`actions[]`、`privacy_status`、`delivery_status`。即使后端某阶段尚未完成，页面也能明确显示“未接入/未知”，而非空白或伪数据。

# 安康 0.19.0：一个产品、两个入口

日期：2026-10-06。用户授权统一电脑/手机交付、整理 main，并将重复实现保留在分支。此次不是重新制定医疗规则，也不是建立云账号平台。

## 产品结构

| 页面 | 默认看到什么 | 次级能力放在哪里 |
| --- | --- | --- |
| 首页 | 康复管家入口、少量今日安排 | 头像进入档案和手机连接；详情进入对应页面 |
| 康复 | 下一项动作、当前条件、下一步按钮、日期安排 | “管理计划与日期”展开生成、编辑、选择、版本与安排 |
| 健康 | 本人资料、拍照/上传、最近记录 | 康复报告、原件、OCR、历史与回收站按需查看 |
| 用药 | 选定日期的每一次服用安排 | 编辑药物和时间；逐次更正及审计；原每日核对保留 |
| 家庭 | 对方主动共享的近期摘要 | 关联、逐人类别授权、解除关联；不能编辑对方 |

康复主按钮随真实状态变化：没有计划先评估；有计划但缺少适用评估时“补充评估”；可执行时“开始下一项”；完成后“制定下一轮”。问卷不充当动作测量，手机录像和电脑实时数据不混为同一种依据。

## 双端架构

```text
电脑 ProductWindow ─┐
                   ├─ ProductBackend 单一串行队列 ─ AgentBridge / 原 ProductService
手机 SharedProduct ┘               │
                              本人档案、用药、记录、家庭授权

手机录像分析 ─ 原 CameraManager / SceneController ─ home_rehab.sqlite3
电脑 Runtime ────────────────────────────────┘
                 同库；owner、source_kind、usage_context 仍分别核对
```

- 手机从电脑“我的档案 → 连接我的手机”进入。同一可信局域网，电脑持续运行。不同本人档案各有独立连接；关闭连接立即拒绝后续 API 请求。
- `PhoneHost` 在后台线程启动、异步关闭；Qt 主线程不等待网络服务器或录像分析退出。停止手机连接不会关闭桌面 ProductBackend。
- 每次启动使用新的随机连接码。签名 cookie 绑定当前本人；浏览器字段不能选择其他本人、数据库路径或分析参与者。
- `ProductBackend.call` 为手机使用独立回执队列。电脑和手机共用同一个 Node 写入进程，防止两个缓存实例覆盖健康档案；手机响应不会被 Qt 的轮询消费。
- 录像分析仍使用原测量实现，保存为 `REPLAY_FILE / SELF_USE`。桌面实时记录保持 `LIVE_CAMERA / SELF_USE`。不迁移、不覆盖、不伪造旧数据库。
- 手机可以查看电脑计划并安排日期；实际执行遵守原来源和适用条件。复杂人工编辑保留电脑入口。手机录像评估、计划、训练仍走原流程。
- 家庭邀请码与本人手机连接码不同。邀请建立关系后默认没有共享类别；按人、按类别显式开放，家庭摘要只读。
- 手机资料上传保留原件，OCR 先进入可核对草稿，经原 Agent 确认再形成记录。没有“拍照后无条件写入健康事实”。
- 浏览器 HTTP 的录音/实时摄像头限制明确展示；文件拍摄上传和键盘语音作为可用入口。未提供公网服务、云登录或跨互联网同步。

## 界面与组件决策

继续应用项目内 [UI polish](../../.agents/skills/ui-polish/SKILL.md)、[frontend-design](../../.agents/skills/frontend-design/SKILL.md) 和 Qt 原生 Fluent 实践；本轮用户的双端整合授权覆盖纯视觉流程的范围限制，但不授权改变测量和医疗结论。

| 需求 | 检索/来源 | 采用方式与取舍 |
| --- | --- | --- |
| 五页导航 | 项目组件检索工具；[React Bits Branched Menu](https://reactbits.dev/c/micro/branched-menu) | 实际检索并阅读注册表源码/Props。五个并列目的地不适合层级分叉菜单，不引入该组件或 React 运行时 |
| 选项切换 | 现有 Qt RubberSegment 适配与原生控件 | 保留已有受限微交互，不增加无意义动画；不声称本轮新移植了 React Bits |
| 弹窗、焦点、Escape | [WAI-ARIA Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) | 手机用原生 dialog；桌面用 Qt 原生窗口行为。计划编辑器保留 hide 后再转换嵌入的修复 |
| 表单与日期 | 浏览器原生 input/select/date；Qt 既有日期控件 | 保留键盘与移动端系统选择器、表单约束、焦点提示，避免重新造普通控件 |
| 导航图标 | 本轮简单线性 SVG；桌面现有图标 | 同一线宽和五页语义，文字始终可见，不依赖图标猜操作 |

视觉采用黑白灰、少量状态色；手机正文 16px、次级 13–14px，主按钮至少 44px；以排版和分隔线组织信息，避免大量等权卡片。按钮只保留短暂按压反馈，支持 reduced-motion。桌面沿用已有字体、浅/深色语义 tokens。无粒子、霓虹、大面积渐变或宣传型模板。

React Bits 注册表当前许可证含 Commons Clause，不能笼统当作纯 MIT。本轮未复制新的 React Bits 实现；来源锁仍在 `tools/ui-polish/sources.lock.json`。

## 后续优先级

先做真实手机、同一 Wi-Fi、防火墙及真人动作验收，再决定是否需要 HTTPS 或独立手机安装包。云账号、异地家庭共享、独立离线双端同步属于下一阶段架构工作，不能由当前局域网连接替代。

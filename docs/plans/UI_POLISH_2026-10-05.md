## Audit and design brief

Fresh pre-edit run: validate_five_pages.py; baseline copied to ignored qa-output/polish-before. Actual screenshots opened for all five main pages. Windows renderer, system Chinese font, DPR 1.5.

Observed: full-width reading fragments make headers/actions drift apart; archive summary and metric controls lack grouping; dates look like unstyled underlined fields; outlined secondary buttons compete with primary actions; underline tabs lack continuity. No decorative graphs, invented numbers or redundant statistics will be added.

Direction: a quiet personal care workspace. White reading surface, subtle neutral grouping for conversation and archive, bounded reading width; tables remain tables, with readable left-aligned headers. Microsoft YaHei UI, 14px body / 20px section / 26px greeting, comfortable native hit areas. Light palette: white #ffffff, neutral #f6f6f6/#ededed, ink #252525, secondary vendor Fluent token, borders #d4d4d4; dark counterparts use existing tokens. Controls 6px, grouped surfaces 12px, no shadows/gradients. Layouts remain page-specific.

Self-critique: do not turn the greeting into a landing hero or the archive into identical cards. One restrained conversation area; archive summary is a single document section; dated care is a row-based table. Existing voice/chat accepted flow remains intact.

## Procurement

Used skills: .agents/skills/{ui-polish,pyside6-fluent-ui,ui-ux-pro-max,frontend-design}/SKILL.md. Focused local UX search: readable desktop data table hierarchy density. Qt official QTabBar/QComboBox documentation reviewed. Registry retrieval via discover-components.mjs all; component source/props/dependencies inspected; live browser preview clicked for RubberSegment and GlideSelect.

| Primitive | Candidate / decision |
|---|---|
| Tabs | React Bits RubberSegment: adapt elastic leading/trailing edge travel and settling into native QTabBar paint; retain keyboard, accessibility, hidden/disabled tabs, signals and reduced motion. No drag/flick to avoid changing navigation behavior. |
| Select | GlideSelect: retain QComboBox model/native popup/keyboard; do not replace with a custom popup simply for a gliding highlight. Style its existing affordance. |
| Input | PromptBar: compare against accepted native composer. Do not add a busy Stop button without the frozen cancellation contract. |
| Tooltip | WarmTooltip: native QToolTip already mature; custom velocity/lean has little patient value, rejected. |
| Navigation/menu | BranchedMenu: tree hierarchy does not match five stable destinations; retained native navigation with existing moving rail. |
| Toast | Existing persistent notice + reveal_receipt: retain real receipt semantics; no swipe/autodismiss of medical/error feedback. |
| Switch | Qt checkbox with text/keyboard/state; no new semantic toggle added. |

Sources: https://reactbits.dev/c/micro/rubber-segment, https://reactbits.dev/c/micro/glide-select, https://reactbits.dev/c/micro/prompt-bar, https://reactbits.dev/c/micro/warm-tooltip, https://reactbits.dev/c/micro/branched-menu.
